# ragas 多跳测试集元评估与清洗

## 一、问题背景
- 测试集本身存在**噪音、幻觉、逻辑退化**，评测结果将失去指导意义
- 元评估（Meta-Evaluation）= 评估「评测数据集本身」的质量
- Ragas 0.4.3 提供四大黄金方法

## 二、方法一：自检清洗（Self-Evaluation）
利用 Ragas 自己的指标对生成样本「逆向跑分」。

### 1. 标准答案忠实度自检（Self-Faithfulness Check）
- 操作：将 `reference` 作为 `response`，`reference_contexts` 作为 `retrieved_contexts`，跑 `Faithfulness` 指标
- 公式：
  Faithfulness Score = supported_claims / total_claims
- 判定：标准答案基于参考上下文生成，理论上得分**必须为 1.0**
- 低于 1.0 → LLM 在生成标准答案时产生**自主幻觉**，样本应剔除

### 2. 问题-答案相关性自检（Self-Relevancy Check）
- 操作：计算 `user_input` 与 `reference` 之间的 `Answer Relevancy`
- 原理：逆向工程反推问题，计算向量余弦相似度
- 判定：得分过低 → 问题与黄金答案风马牛不相及，样本应过滤

## 三、方法二：多跳逻辑退化过滤（Multi-hop Logic Verification）
核心：高质量多跳样本必须「**单节点不可答，双节点合并才可答**」

### 单节点可答性过滤（Single-node Answerability Check）
- 用廉价辅助 LLM 双重验证：
  - 验证 1：只输入 Node A → 答 `user_input`
  - 验证 2：只输入 Node B → 答 `user_input`
- 判定：
  - 任一节点单独能完整回答 → **逻辑退化**为单跳问题
  - 合格样本：单独任一节点**均无法**回答，**双节点合并才能**回答

## 四、方法三：图谱结构与场景多样性审计（Diversity & Structure Audit）

### 1. 关系边多样性审计
- 检查 `KnowledgeGraph` 中 `Relationship` 的种类与分布
- 风险：90% 以上的关联边依赖同一种弱关联（如极低阈值的 `keyphrases_overlap`）
- 健康图谱：混合使用
  - `JaccardSimilarityBuilder`
  - `OverlapScoreBuilder`
  - 多种关系构建器

### 2. 场景矩阵分布审计
- 审计 `Scenario` 列表在不同维度上的信息熵：
  - **用户画像 Persona**：初级员工 / 招聘经理 / 资深开发 等比例均衡
  - **查询风格 Query Style**：Web search vs Chat 占比合理
  - **查询长度 Query Length**：Short / Medium / Long 分布均匀

## 五、方法四：人工专家抽样审计（Human-in-the-Loop Audit）
- 建议抽取 **5% ~ 10%** 样本人工审查
- 三大维度：
  - **语言自然度（Naturalness）**：是否带「翻译腔」/ 模板痕迹，是否符合人类真实提问习惯
  - **问题合理性（Reasonability）**：跨文档推理关联在现实业务中是否有意义
    - 反例：「GitLab 的招聘流程与圆桌会议的茶歇点心有什么关系？」（强行关联）

## 六、关键概念速查
| 概念 | 说明 |
|------|------|
| Meta-Evaluation | 元评估，评估测试集本身质量 |
| Self-Faithfulness Check | 标准答案忠实度自检 |
| Self-Relevancy Check | 问题-答案相关性自检 |
| Single-node Answerability Check | 单节点可答性过滤 |
| 逻辑退化 | 多跳问题退化为单跳 |
| Relationship 多样性 | 图谱中关系构建器种类均衡 |
| 信息熵审计 | Scenario 在多维度上的分布均匀度 |
| Human-in-the-Loop Audit | 人工专家抽样审计（5%~10%） |
