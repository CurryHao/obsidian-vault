# ragas 多跳查询生成与知识图谱关系构建

## 一、问题背景
传统 RAG 测试集生成基于「单文档切片提问」，无法制造「需要跨多文档检索+推理」的复杂问题。
ragas 通过**多跳查询（Multi-Hop Query）** + **基于知识图谱的测试集生成**解决这一痛点。

## 二、整体链路（三阶段）

### 阶段 1：建立跨文档关系链（Relationships Across Documents）
- 读入多篇源文档，类型 `NodeType.DOCUMENT`
- 通过切分器（如 `HeadlineSplitter`）拆为细粒度节点 `NodeType.CHUNK`
- 提取器从每个 chunk 抽取特征：
  - `NERExtractor` —— 命名实体
  - `KeyphrasesExtractor` —— 关键概念短语
- 关系构建器横向对比不同文档的节点属性：
  - `OverlapScoreBuilder`
  - `JaccardSimilarityBuilder`
- 当文档 A 的 chunk 与文档 B 的 chunk 在实体/概念上重合度 > `threshold`，建立关系边

### 阶段 2：寻找跨文档节点对（Finding Node Pairs）
- `MultiHopQuerySynthesizer` 遍历知识图谱
- 检索满足特定连接关系的跨文档节点对：**Node A - Relationship - Node B**
- 实例（来自 `ragas_multihop_gen.py`）：
  - 文档 A：`hiring_policy.md`（GitLab 招聘政策，提到「招聘经理需接受 DIB 培训」）
  - 文档 B：`dib_initiatives.md`（DIB 倡议，提到「DIB 团队举办季度圆桌会议」）
  - 图谱构建器通过核心词「DIB」将两篇完全独立的文档强行关联

### 阶段 3：跨文档逻辑推理与 Q&A 合成（Cross-Document Reasoning）
- 锁定节点对 → 设计生成场景（Scenario）→ 交给 LLM 推理
- LLM 同时读 Node A + Node B 上下文
- 寻找**逻辑交集**，合成**必须结合两篇文档**才能回答的复杂问题
- 输出：
  - `user_input`：跨文档问题（如「GitLab 如何确保 DIB 圆桌会议在促进多样性方面行之有效？」）
  - `reference`：融合两文档事实信息的黄金参考答案

## 三、核心价值
彻底摆脱「单一文档切片提问」局限，制造高度契合现实中「复杂、需跨多文档检索推理」的黄金评测数据集。

## 四、关键概念速查
| 概念 | 说明 |
|------|------|
| `NodeType.DOCUMENT` | 源文档节点 |
| `NodeType.CHUNK` | 切分后的文本块节点 |
| `HeadlineSplitter` | 基于标题的切分器 |
| `NERExtractor` | 命名实体提取器 |
| `KeyphrasesExtractor` | 关键概念短语提取器 |
| `OverlapScoreBuilder` | 重叠度关系构建器 |
| `JaccardSimilarityBuilder` | Jaccard 相似度关系构建器 |
| `threshold` | 关系建立的相似度阈值 |
| `MultiHopQuerySynthesizer` | 多跳查询合成器 |
| Scenario | 节点对对应的生成场景 |
