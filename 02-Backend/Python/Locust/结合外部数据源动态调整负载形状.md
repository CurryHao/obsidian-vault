# 结合外部数据源动态调整负载形状

## 结合外部数据源动态调整负载形状：从被动曲线到主动智能压测

在真实的混沌工程与容量规划中，负载不应由死板的数学公式决定，而应**实时响应外部系统的状态**（如目标服务 CPU 飙升则自动降载），或**由外部业务事件触发**（如促销指令、部署信号）。Locust 的 `LoadTestShape` 本质上是一个**每秒执行一次的 Python 函数**，这为我们整合任何外部数据源（Prometheus、Redis、Kafka、PostgreSQL、甚至 HTTP API）提供了无限可能。

---

### 核心架构原则（分布式必读）

在分布式模式下（Master + Workers），**只有 Master 节点执行 `tick()` 方法**，Worker 被动接收目标用户数。因此：

1. **所有外部数据源 Client 仅在 Master 上实例化**（或在 `tick()` 中判断 `isinstance(self.runner, MasterRunner)`）。
2. **缓存与防抖**：`tick()` 每秒调用一次，直接每次查询数据库/Prometheus 会导致性能灾难。必须实现 **TTL 缓存**（如每 10~30 秒拉取一次）。
3. **故障容错**：外部源宕机时，应返回**缓存值**或**安全降级值**（如维持当前负载），避免压测进程崩溃。

---

### 策略一：基于 Prometheus 实时指标的反向压力控制（闭环自适应）

这是**全自动容量探测**的终极形态：实时拉取目标服务的 CPU/内存/错误率，动态决定下一秒的并发数。

```python
# prometheus_adaptive_shape.py
from locust import LoadTestShape
from locust.runners import MasterRunner
import time
import requests
from typing import Optional
import json

class PrometheusAdaptiveShape(LoadTestShape):
    """
    从 Prometheus 拉取目标服务错误率，自动调整负载：
    - 错误率 < 0.1%: 增加 10% 用户（激进探索）
    - 错误率 0.1%~1%: 维持不变（稳定区）
    - 错误率 > 1%: 快速减少 30% 用户（紧急避险）
    """
    # Prometheus 配置
    PROMETHEUS_URL = "http://prometheus:9090/api/v1/query"
    QUERY = 'sum(rate(http_requests_total{status=~"5.."}[1m])) / sum(rate(http_requests_total[1m]))'
    
    # 自适应参数
    min_users = 50
    max_users = 10000
    current_users = 200
    cache_ttl = 15  # 秒（避免频繁查询）
    
    def __init__(self):
        super().__init__()
        self._cache = None          # (error_rate, timestamp)
        self._session = requests.Session()  # 复用连接

    def _fetch_error_rate(self) -> Optional[float]:
        """拉取错误率，返回 0~1 浮点数，失败返回 None"""
        try:
            resp = self._session.get(
                self.PROMETHEUS_URL,
                params={"query": self.QUERY},
                timeout=5
            )
            if resp.status_code == 200:
                data = resp.json()
                if data["status"] == "success" and data["data"]["result"]:
                    # 注意：Prometheus 返回的是字符串，需转换
                    value_str = data["data"]["result"][0]["value"][1]
                    return float(value_str)
        except Exception as e:
            print(f"[Prometheus] 查询失败: {e}")
        return None

    def _get_error_rate(self) -> float:
        """带缓存与降级的获取方法"""
        now = time.time()
        if self._cache and (now - self._cache[1] < self.cache_ttl):
            return self._cache[0]
        
        # 拉取最新数据
        rate = self._fetch_error_rate()
        if rate is None:
            # 降级：返回 0（假设健康），或维持上次缓存值
            if self._cache:
                rate = self._cache[0]
            else:
                rate = 0.0
        else:
            self._cache = (rate, now)
        return rate

    def tick(self):
        # 仅在 Master 上执行
        if not isinstance(self.runner, MasterRunner):
            return self.current_users, 10  # Worker 忽略

        error_rate = self._get_error_rate()
        
        # 闭环控制算法
        if error_rate < 0.001:  # < 0.1%
            # 加性增长（慢启动）
            increment = max(10, int(self.current_users * 0.1))
            self.current_users = min(self.max_users, self.current_users + increment)
            action = f"⬆ +{increment} (Error={error_rate:.4f})"
        elif 0.001 <= error_rate < 0.01:  # 0.1% ~ 1%
            # 保持稳定
            action = f"➡ 保持 (Error={error_rate:.4f})"
        else:  # > 1%
            # 乘性减少（快速撤退）
            decrement = int(self.current_users * 0.3)
            self.current_users = max(self.min_users, self.current_users - decrement)
            action = f"⬇ -{decrement} (Error={error_rate:.4f})"
        
        # 每 10 秒打印一次状态（便于调试）
        if int(time.time()) % 10 == 0:
            print(f"[{time.strftime('%H:%M:%S')}] {action} | Users={self.current_users}")
        
        # 返回给 Workers
        spawn_rate = max(5, abs(self.current_users - (self.runner.user_count if self.runner else 0)) // 5)
        return self.current_users, int(spawn_rate) + 1
```
**执行命令**：
```bash
# 必须分布式模式启动（Master 拉取指标，Worker 执行压力）
locust -f prometheus_adaptive_shape.py --master --web-port=8089
# 在另一终端/机器启动 Worker
locust -f prometheus_adaptive_shape.py --worker --master-host=<master_ip>
```

### 策略二：Redis 消息队列驱动（外部业务事件触发脉冲）

适用于**外部决策系统**（如运维巡检脚本、监控告警）实时控制压测流量。例如：收到 Kafka 的"大促开启"信号后，立即触发 5 万并发脉冲。

```python
# redis_event_driven_shape.py
from locust import LoadTestShape
from locust.runners import MasterRunner
import redis
import json
import time

class RedisEventShape(LoadTestShape):
    """
    监听 Redis 频道 'locust:control'，接收外部指令：
    - {"action": "set_users", "target": 5000, "duration": 120}
    - {"action": "spike", "peak": 10000, "ramp": 30}
    """
    REDIS_HOST = "redis.example.com"
    REDIS_PORT = 6379
    CHANNEL = "locust:control"
    
    def __init__(self):
        super().__init__()
        self.current_target = 100
        self.spike_end_time = 0
        self.spike_peak = 0
        self.last_cmd_time = 0
        
        # 仅在 Master 上连接 Redis
        if isinstance(self.runner, MasterRunner) or self.runner is None:
            try:
                self.redis_client = redis.Redis(host=self.REDIS_HOST, port=self.REDIS_PORT, decode_responses=True)
                # 订阅频道（使用 PubSub）
                self.pubsub = self.redis_client.pubsub()
                self.pubsub.subscribe(self.CHANNEL)
                print(f"[Redis] 已订阅频道: {self.CHANNEL}")
            except Exception as e:
                print(f"[Redis] 连接失败: {e}")
                self.pubsub = None
        else:
            self.pubsub = None

    def _process_commands(self):
        """处理 Redis 消息（非阻塞）"""
        if not self.pubsub:
            return
        
        # 获取所有待处理消息（非阻塞）
        while True:
            message = self.pubsub.get_message(timeout=0.01)
            if not message:
                break
            if message['type'] == 'message':
                try:
                    cmd = json.loads(message['data'])
                    action = cmd.get('action')
                    
                    if action == 'set_users':
                        self.current_target = int(cmd['target'])
                        # 若设置了持续时间，则用 spike 逻辑，否则永久维持
                        if 'duration' in cmd:
                            self.spike_end_time = time.time() + int(cmd['duration'])
                            self.spike_peak = self.current_target
                        print(f"[Redis] 收到指令: 目标用户 -> {self.current_target}")
                        
                    elif action == 'spike':
                        peak = int(cmd['peak'])
                        ramp = int(cmd.get('ramp', 30))
                        # 立即执行脉冲爬升
                        self.current_target = peak
                        self.spike_end_time = time.time() + ramp + int(cmd.get('hold', 60))
                        self.spike_peak = peak
                        print(f"[Redis] 收到脉冲指令: 峰值 {peak}, 持续 {cmd.get('hold', 60)}s")
                        
                except Exception as e:
                    print(f"[Redis] 解析指令失败: {e}")

    def tick(self):
        # 处理外部指令
        self._process_commands()
        
        run_time = self.get_run_time()
        
        # 检查脉冲是否到期
        if self.spike_end_time > 0 and time.time() > self.spike_end_time:
            # 脉冲结束，回落基线
            self.current_target = 100
            self.spike_end_time = 0
            print("[Redis] 脉冲结束，回落基线 100")
        
        # 如果当前用户数与目标差距过大，快速爬升
        current_actual = self.runner.user_count if self.runner else 0
        diff = self.current_target - current_actual
        spawn_rate = max(10, abs(diff) // 5 if diff > 0 else 10)
        
        return self.current_target, int(spawn_rate) + 1
```

### 策略三：PostgreSQL/InfluxDB 动态时间切片（超大规模历史回放）

相比一次性加载整个 CSV 到内存，使用数据库按 **当前运行时间** 实时查询，支持 TB 级历史流量数据存储。

```python
# db_timeseries_shape.py
from locust import LoadTestShape
from locust.runners import MasterRunner
import psycopg2
from datetime import datetime, timedelta
import time

class PostgreSQLReplayShape(LoadTestShape):
    """
    从 PostgreSQL 按秒级时间戳动态查询历史用户数。
    表结构: traffic_log (timestamp TIMESTAMP, user_count INT)
    """
    DB_DSN = "host=postgres.example.com dbname=locust user=admin password=secret"
    # 设定回放的起始时间（如回放昨天上午 8 点开始的数据）
    REPLAY_START = datetime.now().replace(hour=8, minute=0, second=0, microsecond=0) - timedelta(days=1)
    
    def __init__(self):
        super().__init__()
        self.conn = None
        self.cursor = None
        self._cache = {}  # 小范围缓存（当前秒±5秒）
        self._cache_time = 0
        
        if isinstance(self.runner, MasterRunner) or self.runner is None:
            self.conn = psycopg2.connect(self.DB_DSN)
            self.cursor = self.conn.cursor()
            print("[DB] 已连接 PostgreSQL")

    def _query_users(self, run_time_seconds: float) -> int:
        """查询指定运行秒对应的用户数"""
        # 计算实际时间戳
        query_time = self.REPLAY_START + timedelta(seconds=run_time_seconds)
        
        # 简单缓存：防止每秒都查
        cache_key = int(run_time_seconds)
        if cache_key in self._cache:
            return self._cache[cache_key]
        
        try:
            self.cursor.execute(
                "SELECT user_count FROM traffic_log WHERE timestamp >= %s ORDER BY timestamp LIMIT 1",
                (query_time,)
            )
            row = self.cursor.fetchone()
            if row:
                val = int(row[0])
                self._cache[cache_key] = val
                # 限制缓存大小
                if len(self._cache) > 60:
                    self._cache.clear()
                return val
        except Exception as e:
            print(f"[DB] 查询失败: {e}")
        
        # 降级
        return 100

    def tick(self):
        if not self.conn:
            return 100, 10
        
        run_time = self.get_run_time()
        target = self._query_users(run_time)
        
        # 若超过数据总时长，停止
        if run_time > 86400:  # 假设数据只有 24 小时
            return None
        
        spawn_rate = max(5, target // 20)
        return target, int(spawn_rate) + 1
```

### 策略四：外部控制 API（人工接管 + 自动化脚本联动）

通过暴露一个简单的 Flask API，允许测试经理在压测过程中**手动介入调整并发**，无需重启压测。

```python
# api_controlled_shape.py
from locust import LoadTestShape
from locust.runners import MasterRunner
from flask import Flask, request, jsonify
import threading
import time

# 独立 Flask 服务（嵌入在 Master 进程中）
app = Flask(__name__)
target_users_store = {"value": 100, "updated_at": time.time()}

@app.route('/control/target', methods=['POST'])
def set_target():
    data = request.json
    if 'users' in data:
        target_users_store['value'] = int(data['users'])
        target_users_store['updated_at'] = time.time()
        return jsonify({"status": "ok", "users": target_users_store['value']})
    return jsonify({"error": "missing 'users'"}), 400

@app.route('/control/status', methods=['GET'])
def get_status():
    return jsonify(target_users_store)

class APIControlShape(LoadTestShape):
    def __init__(self):
        super().__init__()
        if isinstance(self.runner, MasterRunner) or self.runner is None:
            # 在 Master 上启动 Flask 线程
            threading.Thread(target=lambda: app.run(host='0.0.0.0', port=5556, debug=False, use_reloader=False), daemon=True).start()
            print("[API] 控制接口已启动: http://<master_ip>:5556/control/target")

    def tick(self):
        global target_users_store
        target = target_users_store.get('value', 100)
        spawn_rate = max(5, target // 10)
        return target, int(spawn_rate) + 1
```

**外部调用**（如 Jenkins 脚本）：
```bash
curl -X POST http://<master_ip>:5556/control/target -H "Content-Type: application/json" -d '{"users": 2000}'
```

### 关键调优与故障处理表

| 外部源类型 | 推荐缓存 TTL | 故障降级策略 | 分布式注意事项 |
|-----------|-------------|-------------|---------------|
| **Prometheus** | 10~30 秒 | 返回 0 错误率（乐观）或维持上次值 | 仅在 Master 查询，避免 100 个 Worker 同时打爆 Prometheus |
| **Redis PubSub** | 实时（事件驱动） | 维持当前缓存目标值 | 所有 Worker 无需连接，仅 Master 订阅 |
| **PostgreSQL** | 5~10 秒（或按秒缓存） | 返回默认基线（如 100） | 使用连接池（psycopg2.pool），Master 独占连接 |
| **外部 HTTP API** | 根据 API 速率限制（如 60 秒） | 返回上次成功值或默认值 | 使用 `requests.Session` 复用 TCP 连接 |

**监控外部源自身**：建议在 `tick()` 中记录 `external_fetch_duration`，若超过 1 秒则告警（可能拖慢压测调度）。

### 总结与最佳实践

1. **数据源独立于压测脚本**：将外部 Client 的初始化放在 `__init__` 中，并严格判断 `MasterRunner`。
2. **慢外部源隔离**：如果外部 HTTP 响应慢（> 100ms），请使用 **异步线程池** 预取数据（`gevent.spawn`），避免阻塞 `tick()` 的主循环。
3. **可观测性**：在自定义指标（如 Prometheus gauge）中暴露 `target_users_from_external`，便于在 Grafana 中对比 **预期负载 vs 实际负载**。
4. **安全边界**：无论外部源返回什么，都使用 `min(max(target, MIN_USERS), MAX_USERS)` 钳制，避免灾难性误操作。
