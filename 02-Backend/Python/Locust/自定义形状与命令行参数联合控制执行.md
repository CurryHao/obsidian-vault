# 自定义形状与命令行参数联合控制执行

## 自定义形状与命令行参数联合控制执行：构建可配置的智能压测引擎

Locust 原生并未提供 `--shape-args` 这类直接传参，但其基于 **Python 事件驱动** 的架构允许我们通过 **自定义 CLI 参数**（`init_command_line_parser`）与 **环境变量** 的组合，实现对 `LoadTestShape` 运行时的完全控制。这使得同一份形状脚本可以在 CI/CD 流水线中具备极高的复用性，无需修改代码即可切换模式、调整峰值、设定持续时间。

本章将提供 **3 种联合控制方案**，从基础到高阶，适配单机、分布式与容器化环境。

---

### 核心机制：注册自定义命令行参数

Locust 2.x 提供了 `events.init_command_line_parser` 钩子，用于向主解析器添加自定义参数。这些参数会被注入到 `environment.parsed_options` 中，在 `LoadTestShape` 的 `tick()` 方法内可随时读取。

```python
# cli_integrated_shape.py
from locust import LoadTestShape, events
from locust.runners import MasterRunner
import argparse
import math
import os

# ------------------- 1. 注册自定义 CLI 参数 -------------------
@events.init_command_line_parser.add_listener
def init_parser(parser):
    # 形状模式选择
    parser.add_argument(
        "--shape-mode",
        type=str,
        default="step",
        choices=["step", "wave", "spike", "diurnal"],
        help="负载形状模式: step(阶梯), wave(波浪), spike(脉冲), diurnal(日周期)"
    )
    # 核心数值参数（支持命令行覆盖）
    parser.add_argument("--peak-users", type=int, default=1000, help="峰值并发用户数")
    parser.add_argument("--min-users", type=int, default=10, help="最小基线用户数")
    parser.add_argument("--step-duration", type=int, default=120, help="阶梯保持时间(秒)")
    parser.add_argument("--test-duration", type=int, default=3600, help="最大测试运行时间(秒)")

# ------------------- 2. 智能形状类（读取参数与环境变量） -------------------
class SmartShape(LoadTestShape):
    def __init__(self):
        super().__init__()
        # 从 environment 获取解析后的 CLI 参数（在 Master/单机模式下可用）
        # 注意：Worker 节点虽不执行 tick，但为了兼容性，需加保护
        opts = self.environment.parsed_options if hasattr(self.environment, 'parsed_options') else None
        
        # 策略：CLI 参数 > 环境变量 > 代码默认值
        self.mode = self._get_opt_or_env(opts, 'shape_mode', 'SHAPE_MODE', 'step')
        self.peak = self._get_opt_or_env(opts, 'peak_users', 'PEAK_USERS', 1000, int)
        self.min_ = self._get_opt_or_env(opts, 'min_users', 'MIN_USERS', 10, int)
        self.step_duration = self._get_opt_or_env(opts, 'step_duration', 'STEP_DURATION', 120, int)
        self.max_runtime = self._get_opt_or_env(opts, 'test_duration', 'TEST_DURATION', 3600, int)
        
        # 状态变量
        self.current_target = self.min_
        self.last_switch_time = 0
        self.spike_end_time = 0
        
        print(f"[Shape 初始化] 模式={self.mode}, 峰值={self.peak}, 最小={self.min_}, 时长={self.max_runtime}s")

    @staticmethod
    def _get_opt_or_env(opts, opt_name, env_name, default, cast_type=str):
        """辅助：从 CLI 或环境变量取值，带类型转换"""
        # 1. 优先 CLI
        if opts and hasattr(opts, opt_name):
            val = getattr(opts, opt_name)
            if val is not None:
                return cast_type(val)
        # 2. 其次环境变量
        env_val = os.getenv(env_name)
        if env_val is not None:
            try:
                return cast_type(env_val)
            except ValueError:
                pass
        # 3. 默认
        return default

    def tick(self):
        # 仅在 Master 或单机模式下执行（分布式 Worker 跳过）
        if self.runner and not isinstance(self.runner, MasterRunner):
            # 如果是 Worker，维持当前状态（实际上 Worker 不会调用 tick，但安全处理）
            return self.current_target, 10

        run_time = self.get_run_time()
        
        # ---------- 自动停止条件 ----------
        if self.max_runtime > 0 and run_time >= self.max_runtime:
            print(f"[{run_time:.0f}s] 达到预设运行时长 {self.max_runtime}s，停止测试")
            return None

        # ---------- 根据模式计算目标并发数 ----------
        target = self.min_
        
        if self.mode == "step":
            # 阶梯模式：每 step_duration 秒增加一步
            step_index = int(run_time // self.step_duration) + 1
            target = min(self.peak, self.min_ + step_index * 50)  # 每步 +50
            
        elif self.mode == "wave":
            # 波浪模式：正弦波（周期 = step_duration * 3）
            period = self.step_duration * 3
            amplitude = (self.peak - self.min_) / 2
            offset = (self.peak + self.min_) / 2
            target = int(offset + amplitude * math.sin(2 * math.pi * run_time / period))
            target = max(self.min_, min(self.peak, target))
            
        elif self.mode == "spike":
            # 脉冲模式：每 300 秒触发一次 60 秒脉冲
            cycle = 300
            pulse_width = 60
            pos_in_cycle = run_time % cycle
            if pos_in_cycle < pulse_width:
                # 脉冲期间：快速爬升到峰值
                progress = pos_in_cycle / pulse_width
                target = int(self.min_ + (self.peak - self.min_) * (progress ** 0.6))  # 先快后慢
            else:
                target = self.min_
                
        elif self.mode == "diurnal":
            # 日周期（24小时模拟）：晨昏双峰
            day_progress = (run_time % 86400) / 86400  # 0~1
            # 双峰高斯近似：8点(0.33)和18点(0.75)
            morning = math.exp(-((day_progress - 0.33) ** 2) / (2 * 0.05 ** 2))
            evening = math.exp(-((day_progress - 0.75) ** 2) / (2 * 0.06 ** 2))
            factor = 0.3 + 0.7 * max(morning, evening)
            target = int(self.min_ + (self.peak - self.min_) * factor)
            
        # 钳制安全范围
        target = max(1, target)
        
        # 动态调整 spawn_rate（平滑爬坡）
        current_actual = self.runner.user_count if self.runner else 0
        diff = target - current_actual
        if diff > 0:
            spawn_rate = max(5, diff // 5)  # 5秒内爬完
        else:
            spawn_rate = max(5, abs(diff) // 2)  # 下降可稍快
        
        self.current_target = target
        return target, int(spawn_rate) + 1
```

### 场景实战：通过命令行自由切换模式

#### 1. 基础执行（使用默认参数）
```bash
# 默认 step 模式，峰值 1000，运行 1 小时
locust -f cli_integrated_shape.py --headless
```

#### 2. 切换为波浪模式，调整峰值为 5000
```bash
locust -f cli_integrated_shape.py \
  --headless \
  --shape-mode wave \
  --peak-users 5000 \
  --test-duration 1800  # 运行30分钟
```

#### 3. 脉冲模式 + 短周期（适合验证弹性伸缩）
```bash
locust -f cli_integrated_shape.py \
  --headless \
  --shape-mode spike \
  --peak-users 10000 \
  --step-duration 30  # 此参数在 spike 中映射为脉冲宽度/周期因子
```

#### 4. 环境变量覆盖（适合 Docker/K8s 注入）
```bash
export SHAPE_MODE=diurnal
export PEAK_USERS=8000
locust -f cli_integrated_shape.py --headless
```

### 高级方案：命令行动态选择不同形状类（多类调度）

若一个文件中定义了多个 `LoadTestShape` 子类（例如 `StepShape`, `WaveShape`, `SpikeShape`），可以通过 CLI 参数 **动态实例化**，避免在单一 `tick()` 中写大量 `if-else`，提升代码可维护性。

```python
# multi_shape_dispatch.py
from locust import LoadTestShape, events
import importlib

# 定义多个形状类（为简洁只列框架）
class StepShape(LoadTestShape):
    def tick(self):
        # 阶梯实现...
        pass

class WaveShape(LoadTestShape):
    def tick(self):
        # 波浪实现...
        pass

class SpikeShape(LoadTestShape):
    def tick(self):
        # 脉冲实现...
        pass

# 全局注册表
SHAPE_REGISTRY = {
    "step": StepShape,
    "wave": WaveShape,
    "spike": SpikeShape,
}

@events.init_command_line_parser.add_listener
def add_cli_args(parser):
    parser.add_argument("--shape-class", type=str, default="step", 
                        choices=list(SHAPE_REGISTRY.keys()),
                        help="选择形状类")

# 关键技巧：在 Locust 启动时，根据 CLI 参数替换默认的 Shape 类
# 方法：通过 events.init 监听器动态设置 environment.shape_class
@events.init.add_listener
def on_locust_init(environment, **kwargs):
    opts = environment.parsed_options
    if opts and hasattr(opts, 'shape_class'):
        class_name = opts.shape_class
        if class_name in SHAPE_REGISTRY:
            # 将 environment.shape_class 替换为选中的类
            # 注意：Locust 内部会实例化它
            environment.shape_class = SHAPE_REGISTRY[class_name]
            print(f"[Init] 形状类已切换为: {class_name}")
        else:
            print(f"[Init] 警告：未知形状类 {class_name}，使用默认")
```

**执行示例**：
```bash
# 使用 WaveShape
locust -f multi_shape_dispatch.py --headless --shape-class wave --peak-users 2000
```

### 分布式模式下的参数同步（Master → Worker）

在分布式模式下，**只有 Master 执行 `tick()`**，Worker 仅负责执行任务。但 Worker 节点同样需要加载相同的 `locustfile.py` 以解析自定义参数（防止 `environment.parsed_options` 为空导致异常）。最佳实践：

1. **在所有节点（Master 和 Worker）部署完全相同的脚本文件**。
2. **Worker 不执行形状逻辑**，但为了安全，在形状类 `tick()` 中加入 `if not isinstance(self.runner, MasterRunner): return None`（或返回默认值）。
3. **参数传递**：Master 通过 `environment.parsed_options` 读取 CLI 参数，并将计算出的 `(target, spawn_rate)` 通过控制协议发送给 Worker。Worker 无需关心 CLI 参数具体值。

**启动命令**：
```bash
# Master（添加所有自定义参数）
locust -f cli_integrated_shape.py --master --web-port=8089 \
       --shape-mode spike --peak-users 8000

# Worker（需指定相同的 -f 文件，但无需重复传参，仅需 --worker）
locust -f cli_integrated_shape.py --worker --master-host=<master_ip>
```

### 结合 CI/CD：动态生成参数化压测任务（Jenkins/GitLab CI）

在流水线中，我们可以将环境变量（如构建号、分支名、目标环境）动态注入：

```yaml
# GitLab CI 示例
stages:
  - performance-test

performance-test:
  stage: performance-test
  script:
    - |
      locust -f cli_integrated_shape.py \
        --headless \
        --host=$TARGET_HOST \
        --shape-mode $LOAD_MODE \
        --peak-users $PEAK_USERS \
        --test-duration $DURATION \
        --csv="reports/load_${CI_COMMIT_SHORT_SHA}" \
        --html="reports/report_${CI_COMMIT_SHORT_SHA}.html"
  variables:
    LOAD_MODE: "wave"
    PEAK_USERS: "3000"
    DURATION: "600"
  artifacts:
    paths:
      - reports/
```

### 进阶：运行时热更新参数（无需重启）

结合之前的 **外部数据源策略**（Redis/API），你可以实现“CLI 参数作为初始值 + 外部源作为动态覆写”的组合：

```python
def tick(self):
    # 1. 从 CLI 获取默认目标
    cli_target = self._compute_cli_based_target(run_time)
    
    # 2. 尝试从 Redis 获取覆写值（若存在则优先）
    override = self._redis_get("locust:override_users")
    if override is not None:
        target = int(override)
    else:
        target = cli_target
    
    return target, spawn_rate
```

这使得压测执行者既可以**预设运行计划**（通过 CLI），又可以在运行中**临时接管控制权**（通过 Redis）。

### 常见问题与调优表

| 问题现象 | 根本原因 | 解决方案 |
|---------|---------|---------|
| 自定义 CLI 参数未生效 | 未注册 `init_command_line_parser` 或参数名错误 | 检查监听器是否在文件顶层；打印 `environment.parsed_options` 调试 |
| 分布式 Worker 启动报 `AttributeError` | Worker 未加载包含 CLI 注册的脚本 | 确保 Worker 使用 `-f` 指向同一个文件 |
| 形状模式切换时用户数跳动剧烈 | `spawn_rate` 计算未考虑差距大小 | 使用 `abs(target - current_actual) // 5` 动态计算 |
| 环境变量与 CLI 同时存在时优先级混乱 | 代码逻辑未明确优先级 | 采用本示例的 `CLI > Env > Default` 清晰分层 |
| 长时间运行后形状停止（返回 None） | `test_duration` 触发或阶段结束 | 确认 `--test-duration` 足够长，或在 `tick()` 中增加日志 |

### 最佳实践总结

1. **参数即配置**：将 `peak_users`, `mode`, `duration` 全部参数化，**消灭硬编码**，使同一脚本适配所有环境（dev/staging/prod）。
2. **分层配置**：CLI 参数 > 环境变量 > 默认值，既满足临时调试，又满足自动化编排。
3. **类型安全**：使用 `argparse` 的 `type` 参数（如 `type=int`）进行输入校验，防止字符串误传。
4. **可观测性**：在 `__init__` 和 `tick()` 关键分支打印当前配置，便于排查“为什么负载不是我预期的”。
5. **分布式一致性**：在 Master 上计算形状，Worker 只执行，避免 Worker 间因时钟偏差导致负载不一致。
