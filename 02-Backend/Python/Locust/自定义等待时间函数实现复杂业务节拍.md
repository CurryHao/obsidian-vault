# 自定义等待时间函数实现复杂业务节拍

当内置的 `between`、`constant` 或 `constant_pacing` 无法满足业务需求时，Locust 允许你**自定义等待时间函数**。这让你能将压测流量从“统计学规律”升级为**“业务规则驱动”**，极其灵活。

在 Locust 中，`wait_time` 可以是一个**可调用对象**（函数或方法），它接受 `self` 参数，返回一个**浮点数**（单位：秒），代表该用户下一次任务的等待间隔。

---

### 1. 基础机制：函数签名与调度逻辑

自定义函数的核心要点：
- **必须接收 `self`**：以便访问当前用户的状态（如 `self.user_id`、`self.token` 或自定义属性）。
- **必须返回数字**：返回 `int` 或 `float`，单位是**秒**。
- **严禁阻塞**：函数体内**绝不能使用 `time.sleep()`** 或进行同步 I/O 操作（如读取慢速文件、同步 Redis 查询），否则会阻塞整个协程调度。

```python
from locust import HttpUser, task
import random
import time

class CustomUser(HttpUser):
    # 定义一个实例方法作为 wait_time
    def my_custom_wait(self) -> float:
        # 这里只做数学运算和状态读取，绝对安全
        base_wait = random.uniform(1, 3)
        # 如果用户是 VIP，缩短等待时间
        if getattr(self, 'is_vip', False):
            return base_wait * 0.5
        return base_wait

    wait_time = my_custom_wait  # 注意：不加括号，传递函数对象
```

### 2. 场景一：状态驱动的动态节拍（用户画像）

根据用户在 `on_start` 中获取的角色标签，动态调整请求频率。

```python
class PersonalizedUser(HttpUser):
    def on_start(self):
        # 模拟从数据库或 Token 中解析用户等级
        resp = self.client.get("/user/profile")
        self.user_tier = resp.json().get("tier", "normal")  # normal, vip, admin

    def dynamic_wait(self):
        if self.user_tier == "admin":
            # 管理员操作极快（后台监控）
            return random.uniform(0.5, 1.0)
        elif self.user_tier == "vip":
            # VIP 用户体验流畅（稍快）
            return random.uniform(1.0, 2.5)
        else:
            # 普通用户正常浏览
            return random.uniform(3.0, 7.0)

    wait_time = dynamic_wait
```

### 3. 场景二：自适应背压（根据服务器响应时间反馈）

这是高级压测策略。如果服务器响应变慢（即将崩溃），增加等待时间以模拟用户“焦躁重试”或“犹豫等待”；如果响应极快，缩短等待时间模拟“秒杀手速”。

```python
class AdaptiveUser(HttpUser):
    def __init__(self, environment):
        super().__init__(environment)
        self.last_rt = 100  # 单位：毫秒

    def adaptive_wait(self):
        # 逻辑：响应时间 > 500ms 时，等待时间线性增加，减轻服务器压力
        # 响应时间 < 100ms 时，快速发起下一个请求
        if self.last_rt > 500:
            # 服务器慢了，用户会多犹豫一会 (2~5 秒)
            return random.uniform(2.0, 5.0)
        elif self.last_rt > 200:
            return random.uniform(0.5, 1.5)
        else:
            # 极速响应，模拟高频操作
            return random.uniform(0.1, 0.3)

    wait_time = adaptive_wait

    @task
    def sensitive_api(self):
        start = time.perf_counter()
        self.client.get("/api/data")
        # 注意：不能在 wait_time 里直接改，要在任务里更新状态
        self.last_rt = (time.perf_counter() - start) * 1000
```

> **注意**：在 `@task` 中更新 `self.last_rt`，在 `wait_time` 中读取，实现了跨方法的数据共享。

### 4. 场景三：基于时间表的业务节拍（模拟早/晚高峰）

利用 Python 的 `datetime` 库，模拟一天中的不同流量形态。

```python
import datetime
import random

class TimeBasedUser(HttpUser):
    def time_sensitive_wait(self):
        now = datetime.datetime.now().hour
        
        # 早上 8~10 点：上班高峰，操作密集
        if 8 <= now <= 10:
            return random.uniform(0.3, 0.8)
        # 中午 12~14 点：午休，操作中等
        elif 12 <= now <= 14:
            return random.uniform(1.0, 2.0)
        # 晚上 22 点后：低峰，极慢
        elif now >= 22:
            return random.uniform(5.0, 10.0)
        # 常规工作时间
        else:
            return random.uniform(1.5, 3.0)

    wait_time = time_sensitive_wait
```

### 5. 场景四：混合分布（帕累托/正态分布叠加）

`between` 只支持均匀分布。若需模拟 **“80% 的请求来自 20% 的突发集中”**（帕累托分布），需自定义。

```python
import random

class ParetoUser(HttpUser):
    def pareto_wait(self):
        # 形状参数 alpha=1.5，尺度参数 scale=1
        # 产生极端的突发等待：大量 <0.5s，少量 >10s
        raw = random.paretovariate(1.5) 
        # 截断防止无限等待，保留尖刺特性
        return min(raw, 8.0)

    wait_time = pareto_wait
```

### 6. 场景五：复杂业务流程的阶段节拍（下单全链路）

在 `SequentialTaskSet` 中，不同步骤应有不同节奏（浏览慢、支付快）。

```python
from locust import SequentialTaskSet, task, HttpUser

class ComplexFlow(SequentialTaskSet):
    def wait_time_for_step(self):
        # 利用当前步骤 ID 或自定义属性决定等待时间
        step = getattr(self, 'current_step', 'browse')
        if step == 'browse':
            return random.uniform(3, 6)
        elif step == 'cart':
            return random.uniform(1, 2)
        elif step == 'pay':  # 支付阶段，操作极短
            return random.uniform(0.2, 0.5)
        return 1.0

    # 在 TaskSet 中重写 wait_time
    wait_time = wait_time_for_step

    @task
    def step_browse(self):
        self.current_step = 'browse'
        self.client.get("/products")
    
    @task
    def step_cart(self):
        self.current_step = 'cart'
        self.client.post("/cart")
    
    @task
    def step_pay(self):
        self.current_step = 'pay'
        self.client.post("/pay")
        self.interrupt()  # 流程结束
```

### 7. 反模式警告（这些会毁掉你的压测）

| 错误写法 | 后果 | 正确姿势 |
| :--- | :--- | :--- |
| **`wait_time = lambda self: time.sleep(1)`** 或在函数内 `sleep` | 阻塞整个 Greenlet，所有用户排队等待，并发数急剧下降。 | **永远不要**在 `wait_time` 里用 `time.sleep`。调度器会自动调用 `gevent.sleep`。 |
| **在 `wait_time` 中发起 HTTP 请求** | 同步阻塞且破坏统计模型。 | 只做数学计算和内存变量读取。需要外部数据时，在 `on_start` 中预加载。 |
| **函数内访问未初始化的 `self.attr`** | `AttributeError` 导致用户崩溃退出。 | 在 `on_start` 或 `__init__` 中初始化所有自定义属性。 |
| **返回 `None` 或负数** | 若返回 `None`，Locust 会报错；负数会被视为 0 等待。 | 确保返回值为 `>=0` 的浮点数。 |
| **直接修改类变量 `cls.wait_time`** | 影响所有用户实例，失去个体差异性。 | 始终通过实例方法 `def wait(self):` 定义，或修改 `self.wait_time`（仅影响当前实例）。 |

### 8. 调试技巧：验证你的等待分布

在压测初期，可以快速打印统计验证逻辑是否正确（注意：线上压测需注释掉打印，避免 I/O 影响性能）。

```python
def debug_wait(self):
    interval = random.expovariate(0.5)
    print(f"User {self.user_id} 等待 {interval:.2f} 秒")
    return interval
```

### 💎 总结

- **自定义 `wait_time` 是 Locust 的灵魂**，它让你从“配置员”变成“架构师”，能将业务 SLO、用户画像、时段策略甚至自适应算法融入压测脚本。
- **黄金法则**：`wait_time` 只做**轻量计算**，返回一个数字。**所有 I/O 操作**（网络、磁盘、数据库）必须放在 `@task` 或 `on_start` 中。
- **设计哲学**：如果业务节奏是固定的（如秒杀），用 `constant_pacing`；如果是复杂多变的（如千人千面推荐流），毫不犹豫地用自定义函数。

如果你想尝试更极端的策略——例如**“根据服务器返回的 Retry-After 头动态调整等待时间”**，或者**“在自定义等待中引入随机游走（Random Walk）模拟用户情绪波动”**，我可以为你写出对应的生产级代码。你更倾向哪种深入方向？
