# 指数分布与均匀分布对压力曲线的影响

在 Locust 中，默认的 `between` 使用的是**均匀分布（Uniform Distribution）**，而**指数分布（Exponential Distribution）**虽然未内置，但可以通过自定义 `wait_time` 轻松实现。

选择哪种分布，本质上决定了你的压力是**“平稳匀速”**还是**“突发脉冲”**。这对于模拟真实流量（如 Web 请求通常呈泊松到达，间隔服从指数分布）或测试弹性扩缩容系统至关重要。

---

### 1. 数学机制与流量特征对比

| 维度 | **均匀分布 `between(a, b)`** | **指数分布 `random.expovariate(1/mean)`** |
| :--- | :--- | :--- |
| **概率密度形状** | **矩形**（在 [a, b] 内概率相等） | **递减曲线**（短间隔极多，长间隔极少，有长尾） |
| **取值范围** | **有界**（严格在 a 和 b 之间） | **无界**（理论可到无穷大，实际受 `max` 限制） |
| **平均等待时间** | `(a+b)/2` | `1 / λ`（λ 为速率参数） |
| **短期波动性** | **低**（每次等待差别不大，节奏均匀） | **极高**（可能连续 3 次等待 0.1 秒，接着突然等待 10 秒） |
| **RPS 曲线形态** | **平坦、平滑**，呈直线型 | **剧烈锯齿、突发尖刺**，间歇性低谷 |

---

### 2. 代码实现：如何复现指数分布

Locust 的 `wait_time` 支持任意可调用对象，因此你可以直接使用 Python 标准库的 `random.expovariate`。

```python
from locust import HttpUser, task
import random

class ExponentialUser(HttpUser):
    # 设定平均等待时间为 2 秒（λ = 1/2 = 0.5）
    # 注意：expovariate 的入参是 λ（速率），而非均值
    def exp_wait(self):
        # 为防止极端长尾（如等待 100 秒）导致用户闲置，建议设置上限
        raw = random.expovariate(1.0 / 2.0)  # 均值 2 秒
        return min(raw, 10.0)  # 截断在 10 秒以内，保留突发特性但避免死锁

    wait_time = exp_wait

    @task
    def browse(self):
        self.client.get("/")
```
均匀分布（基准）**：
```python
class UniformUser(HttpUser):
    # 平均等待也是 2 秒（1~3 秒均匀分布）
    wait_time = between(1, 3) 
```

### 3. 压力曲线的视觉化差异（关键）

假设 **100 个并发用户**，接口响应耗时 **50ms**，运行 5 分钟：

#### A. 均匀分布 (`between(1, 3)`)
- **表现**：每个用户的间隔在 1~3 秒之间缓慢波动。
- **全局 RPS**：稳定在 `100 / (0.05 + 2)` ≈ **48~49 RPS**。
- **曲线特征**：一条**几乎水平的直线**，极其平滑。
- **压测效果**：适合验证系统的**稳态吞吐量**（Capacity Testing）。

#### B. 指数分布 (均值 2 秒)
- **表现**：大量用户等待时间极短（< 0.5 秒），少量用户等待极长（> 5 秒）。
- **全局 RPS**：虽然平均值同为 2 秒，但**瞬时 RPS**会在 **20 RPS ~ 150 RPS** 之间剧烈震荡。
- **曲线特征**：呈现**“锯齿状尖峰”**（Burst）。
- **压测效果**：能有效暴露出系统**弹性扩缩容的滞后性**、**连接池饥饿**以及**GC 停顿**问题。

---

### 4. 深入解读：为什么指数分布更接近“真实世界”？

- **泊松到达过程**：在排队论中，如果大量独立用户互不影响地发起请求，单位时间内的到达数量服从泊松分布（Poisson Distribution），而**相邻两次请求的时间间隔恰恰服从指数分布**。
- **人类行为的实际表现**：真实用户在刷抖音或浏览电商时，并非“每隔 3 秒精准滑动一次”。更多时候是“连续快速滑动 5 次，然后停下来阅读 10 秒”。**指数分布自带的长尾效应能完美模拟这种“短时爆发 + 长时沉寂”的间歇性行为**。

> **结论**：若你的压测目标是**模拟真实公网流量**，指数分布比均匀分布更具生物学和行为学依据。

---

### 5. 对系统资源的隐蔽影响（专家视角）

| 资源维度 | 均匀分布（平滑） | 指数分布（突发） |
| :--- | :--- | :--- |
| **数据库连接池** | 连接数缓慢升降，池子稳定 | 在尖峰时刻瞬间占满所有连接，触发 `Timeout` 异常 |
| **GC（垃圾回收）** | 内存分配平稳，GC 频率固定 | 突发请求瞬间分配大量对象，触发 Full GC，导致响应时间毛刺 |
| **K8s HPA（水平Pod自动伸缩）** | 指标平滑，扩容动作温和 | 指标剧烈抖动，可能触发频繁扩缩容（“振荡”效应） |
| **缓存（Redis）** | 命中率稳定 | 突发流量可能击穿缓存，导致数据库瞬时负载飙升 |

**实战建议**：在做**容量规划**时，优先看均匀分布（评估稳态上限）；在做**韧性测试（Chaos Engineering）**时，强烈推荐指数分布（验证系统抗突发流量能力）。

### 6. 进阶技巧：混合分布与动态调节

你甚至可以自定义更复杂的分布，例如**正态分布（Normal）**或**帕累托分布（Pareto）**，以模拟特定业务场景（如“上班打卡”时间段的高度集中）。

```python
import random
import numpy as np  # 需安装 numpy

class MixedUser(HttpUser):
    def dynamic_wait(self):
        # 80% 概率使用指数分布（突发），20% 概率使用均匀分布（平滑）
        if random.random() < 0.8:
            return min(random.expovariate(0.5), 8)
        else:
            return random.uniform(2, 4)
    
    wait_time = dynamic_wait
```

### 7. 选型决策树（何时选用指数分布）

1. **是否模拟公网用户真实行为？** -> **是**，选择指数分布。
2. **是否测试自动扩缩容（HPA/KEDA）的灵敏度？** -> **是**，选择指数分布制造尖刺。
3. **是否进行数据库/缓存连接池极限测试？** -> **是**，选择指数分布瞬时占满连接。
4. **是否仅需评估系统最大稳定吞吐量（RPS 上限）？** -> **否**，选择均匀分布（更易观测和计算）。

### 💎 总结

- **均匀分布**：用**“确定性”**换取**“稳定性”**，压测曲线像“匀速跑步机”。
- **指数分布**：用**“随机性”**换取**“真实性”**，压测曲线像“高峰期的地铁流量”。

在 Locust 中，只需重写一个 `wait_time` 函数，就能在两种哲学间自由切换。建议你在同一套脚本中保留两个 `User` 类，通过命令行 `--class-picker` 或权重切换，对比同一系统在“平滑压力”和“突发压力”下的不同表现。
