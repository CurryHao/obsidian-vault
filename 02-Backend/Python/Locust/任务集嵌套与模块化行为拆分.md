# 任务集嵌套与模块化行为拆分

任务集嵌套与模块化拆分，是让压测脚本从“单体大杂烩”进化为**可维护、可复用、可组合**的工程化代码的核心手段。通过将不同业务域（如“浏览”、“加购”、“支付”）拆分成独立的 `TaskSet` 类，再通过嵌套组装到 `User` 中，你可以像搭积木一样构建复杂的全链路压测场景。

---

### 1. 核心概念：`TaskSet` 与 `HttpUser` 的关系

-   **`HttpUser`**：扮演“容器”角色，定义全局配置（如 `host`、`wait_time`、`weight`），并拥有一个 `client` 用于发请求。它本身**不直接处理业务逻辑**，而是通过 `tasks` 属性或 `@task` 方法将执行权委托给 `TaskSet`。
-   **`TaskSet`**：扮演“业务模块”角色，封装一组相关的任务（`@task` 方法）。它**共享父级 `HttpUser` 的 `client` 和上下文**。

```python
from locust import HttpUser, TaskSet, task, between

# 定义一个独立的业务模块
class BrowseTasks(TaskSet):
    @task(3)
    def view_home(self):
        self.client.get("/")

    @task(1)
    def view_product(self):
        self.client.get("/product/123")

# 在 HttpUser 中引用该模块
class WebsiteUser(HttpUser):
    wait_time = between(1, 3)
    # 使用 tasks 属性指定顶级任务集（权重可忽略，此处所有任务集均等概率）
    tasks = [BrowseTasks]
```
### 2. 嵌套层级：`SequentialTaskSet` 用于流程控制

`SequentialTaskSet` 是 `TaskSet` 的子类，它会**严格按照方法定义的顺序**执行 `@task` 方法（忽略权重），非常适合模拟有依赖关系的业务流程（如下单、审批流）。

```python
from locust import SequentialTaskSet, task, HttpUser

class OrderFlow(SequentialTaskSet):
    def on_start(self):
        """进入此任务集时自动执行，适合做前置校验"""
        print("开始下单流程")

    @task
    def add_cart(self):
        self.client.post("/cart", json={"id": 123})

    @task
    def apply_coupon(self):
        self.client.post("/coupon", json={"code": "SAVE10"})

    @task
    def pay(self):
        self.client.post("/pay")
        # 支付完成后，退出当前任务集，返回父级任务集或直接退出用户
        self.interrupt()

class MixedUser(HttpUser):
    tasks = {
        BrowseTasks: 5,      # 普通 TaskSet，权重5
        OrderFlow: 1,        # SequentialTaskSet，权重1
    }
```

**关键点**：
-   `SequentialTaskSet` 中，`@task` 的权重参数被忽略，执行顺序由方法在类中的定义顺序决定。
-   必须在流程末尾调用 `self.interrupt()`，否则该任务集结束后会**从头开始重新执行**（即形成无限循环）。

### 3. 模块化拆分的标准模式

#### A. 按业务域拆分
将同一业务域的操作聚合在一个 `TaskSet` 中，便于团队协作和版本管理。

```text
project/
├── locustfile.py          # 主入口，组合各个模块
├── tasks/
│   ├── browse.py          # 浏览相关（首页、搜索、商品详情）
│   ├── cart.py            # 购物车相关（加购、修改数量、删除）
│   ├── order.py           # 订单相关（下单、支付、查询）
│   └── admin.py           # 后台管理（上架商品、查看报表）
```

```python
# tasks/browse.py
from locust import TaskSet, task

class BrowseTasks(TaskSet):
    @task(10)
    def homepage(self): self.client.get("/")
    
    @task(5)
    def search(self): self.client.get("/search?q=test")
```

```python
# tasks/order.py
from locust import SequentialTaskSet, task

class CheckoutFlow(SequentialTaskSet):
    @task
    def add_cart(self): self.client.post("/cart")
    
    @task
    def pay(self):
        self.client.post("/pay")
        self.interrupt()
```

```python
# locustfile.py（主入口）
from locust import HttpUser, between
from tasks.browse import BrowseTasks
from tasks.order import CheckoutFlow

class EcommerceUser(HttpUser):
    wait_time = between(1, 3)
    tasks = {
        BrowseTasks: 8,
        CheckoutFlow: 2,
    }
```

#### B. 按用户角色拆分
不同的用户角色（如“游客”、“会员”、“管理员”）拥有不同的行为集合，可以通过 `TaskSet` 实现行为隔离。

```python
class GuestTasks(TaskSet):
    @task
    def browse(self): self.client.get("/")

class MemberTasks(TaskSet):
    @task
    def browse(self): self.client.get("/")
    
    @task
    def profile(self): self.client.get("/profile")

class AdminTasks(TaskSet):
    @task
    def dashboard(self): self.client.get("/admin")
    
    @task
    def manage_users(self): self.client.post("/admin/user")

# 通过类权重控制各角色的并发比例
class GuestUser(HttpUser):
    weight = 7
    tasks = [GuestTasks]

class MemberUser(HttpUser):
    weight = 2
    tasks = [MemberTasks]

class AdminUser(HttpUser):
    weight = 1
    tasks = [AdminTasks]
```

### 4. 嵌套执行：在 TaskSet 内部调用另一个 TaskSet

你可以在一个 `TaskSet` 的方法中，通过 `self.execute(OtherTaskSet)` 主动切换到另一个任务集，实现更精细的流程编排。

```python
class LoginFlow(SequentialTaskSet):
    @task
    def login(self):
        resp = self.client.post("/login", json={"user": "test"})
        if resp.status_code == 200:
            self.execute(DashboardTasks)  # 登录成功后直接进入仪表盘模块
        else:
            self.interrupt()  # 登录失败则退出整个用户

class DashboardTasks(TaskSet):
    @task
    def view_stats(self): self.client.get("/stats")
    
    @task
    def logout(self):
        self.client.post("/logout")
        self.interrupt()  # 退出任务集，回到 LoginFlow 继续执行（若 LoginFlow 未结束）
```

> **注意**：`self.execute()` 会**阻塞当前方法**，直到被调用的 `TaskSet` 执行完毕（即其中调用了 `self.interrupt()`）后，才会返回原方法继续执行。

### 5. 上下文传递与数据共享（重要）

多个 `TaskSet` 之间需要共享数据（如登录后的 Token、购物车 ID）。可以通过**父级 `HttpUser` 实例的属性**实现跨模块数据传递。

```python
class LoginTaskSet(TaskSet):
    def on_start(self):
        resp = self.client.post("/login")
        # 将 token 存储在父级 HttpUser 中（self.user 指向父级 User 实例）
        self.user.token = resp.json()["access_token"]

class OrderTaskSet(TaskSet):
    @task
    def create_order(self):
        # 读取父级 User 中存储的 token
        token = self.user.token
        self.client.post("/order", headers={"Authorization": f"Bearer {token}"})
```

**跨协程数据隔离**：每个 `User` 实例（协程）拥有独立的属性空间，因此上述方式天然支持**协程级别**的数据隔离，无需额外加锁。

### 6. 高级技巧：抽象基类与接口规范

对于大型项目，可以定义抽象的 `TaskSet` 基类，强制子类实现特定方法，保证代码规范。

```python
from abc import ABC, abstractmethod

class BaseTaskSet(TaskSet, ABC):
    @abstractmethod
    def setup(self):
        """每个模块必须实现初始化方法"""
        pass

    @abstractmethod
    def teardown(self):
        """每个模块必须实现清理方法"""
        pass

class ConcreteTasks(BaseTaskSet):
    def setup(self):
        print("初始化具体模块")

    def teardown(self):
        print("清理具体模块")
    
    @task
    def work(self):
        self.client.get("/")
```

### 7. 常见陷阱与诊断

| 陷阱 | 现象 | 解决方案 |
| :--- | :--- | :--- |
| **任务集嵌套后用户不退出** | `SequentialTaskSet` 执行完后反复从头开始，未调用 `interrupt()` | 在流程末尾或条件满足时调用 `self.interrupt()`。 |
| **数据共享混乱（不同用户串数据）** | 在类属性（`@classmethod`）而非实例属性（`self.user`）中存储数据 | 确保所有可变状态存储在 `self.user` 或 `self` 中，而非类变量。 |
| **模块化后权重失效** | 在 `SequentialTaskSet` 中仍尝试用权重控制顺序 | 理解 `SequentialTaskSet` 忽略权重；若需权重，使用普通 `TaskSet` 并配合 `@task(weight)`。 |
| **过度嵌套导致代码难以追踪** | `TaskSet` 层数超过 3 层，调试困难 | 控制嵌套深度，每个 `TaskSet` 职责单一；必要时使用 `on_start`/`on_stop` 打印进入/退出日志辅助定位。 |

### 💎 总结

-   **`TaskSet` 负责“做什么”**：封装业务逻辑模块（浏览、购物车、支付）。
-   **`HttpUser` 负责“谁来做”**：配置全局参数（`host`、`wait_time`、`weight`）并组装 `TaskSet`。
-   **`SequentialTaskSet` 负责“怎么做流程”**：确保有依赖关系的步骤按顺序执行。
-   **上下文传递**：通过 `self.user` 或 `self.environment` 在模块间共享数据，但要注意实例级别的隔离。
-   **模块化收益**：代码可读性提升、多团队并行开发、场景配置灵活（通过 `tasks` 字典调整权重即可切换流量模型）。
