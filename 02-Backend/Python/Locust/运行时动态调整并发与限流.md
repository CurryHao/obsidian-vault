# 运行时动态调整并发与限流

在 Locust 的官方文档中，并没有 `--web-user` 这个参数。你可能是想了解在 **Web UI 运行期间动态调整用户数** 的方法，或者将其与 **`--max-rps`** 这个用于限制全局请求速率（RPS）的参数弄混了。

下面我将对这两个概念进行详细说明。

### 🖥️ Web UI 运行时动态调整并发

`--web-user` 并非一个有效的 Locust 参数。在 Web UI 模式下，动态调整并发用户数的正确方式有以下几种：

*   **通过 Web UI 界面调整**：在 Web 界面（默认 `http://localhost:8089`）的 `Number of users` 输入框中修改目标用户数，然后点击 `Start` 按钮即可生效。
*   **通过键盘快捷键调整**（适用于 `--headless` 无界面模式）：在运行压测的终端中，可以使用 `w`、`W`、`s`、`S` 键来动态调整用户数。
    *   `w`：增加 1 个用户
    *   `W`：增加 10 个用户
    *   `s`：减少 1 个用户
    *   `S`：减少 10 个用户

### 🚦 全局限流：`--max-rps` 参数

`--max-rps` 是 Locust 提供的一个**全局限流参数**，用于限制整个压测集群（所有 Worker 节点）每秒发出的**总请求数（RPS）**。

它的核心作用是**保护目标服务器**，防止在压测过程中因流量过大而被意外压垮。

#### 使用示例

```bash
# 限制全局 RPS 不超过 500
locust -f my_locustfile.py --headless -u 100 -r 10 --max-rps 500
```
## 注意事项

*   **与 `wait_time` 协同工作**：`--max-rps` 是一个**上限**，实际 RPS 还受 `wait_time` 和系统响应时间的影响。如果 `wait_time` 设置得较长，即使 `--max-rps` 设得很大，实际 RPS 也可能达不到这个上限。
*   **分布式场景**：在 Master-Worker 模式下，`--max-rps` 在 **Master 节点**设置，用于控制**所有 Worker 的全局总 RPS**。
*   **精确性**：`--max-rps` 提供的是**尽力而为**的限流，在高并发场景下可能存在微小误差。

### 💎 总结

*   **`--web-user`**：并非有效参数。在 Web UI 模式下，直接在界面修改 `Number of users` 即可动态调整并发。
*   **`--max-rps`**：有效的**全局限流**参数，用于保护目标服务，防止被意外压垮。
