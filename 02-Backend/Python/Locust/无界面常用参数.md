# 无界面常用参数

无界面模式（Headless）是 Locust 融入 CI/CD 流水线和自动化压测场景的**核心运行方式**。它去掉了 Web 界面，完全通过命令行参数驱动，适合在服务器后台或容器中长时间运行。

下面我按**压测执行的时间顺序**，深度拆解这四个最关键的参数及其协同关系。

---

### 1. 核心参数解析（按执行阶段）

#### A. `--headless`（总开关）
- **作用**：告诉 Locust **不要启动 Web UI**（默认 `http://localhost:8089`），直接进入压测执行状态。
- **效果**：控制台不再提供交互式输入，所有行为由命令行参数决定。

#### B. `--users`（目标并发数，缩写 `-u`）
- **作用**：设定压测最终要达到的**并发用户总数**（即协程数量）。
- **关键点**：这是压测的**目标值**，而非瞬时值。系统会从 0 开始，按照 `--spawn-rate` 逐步爬升到此数值。
- **公式**：总 RPS ≈ `users / (平均响应时间 + 平均等待时间)`。

#### C. `--spawn-rate`（孵化速率，缩写 `-r`）
- **作用**：设定**每秒启动多少个用户**。
- **关键点**：它决定了**爬坡时间（Ramp-up Time）**。如果 `users=1000`，`spawn-rate=100`，则需要 **10 秒**才能达到目标并发。
- **实战建议**：爬坡时间建议至少设为 **1~2 分钟**（即 `rate = users / 120`），让系统有足够的时间触发自动扩容（如 K8s HPA），避免瞬间流量冲击导致误判。

#### D. `--run-time`（运行时长，缩写 `-t`）
- **作用**：设定压测**总执行时长**，到达时间后自动停止并退出进程。
- **格式**：支持 `10s`（秒）、`5m`（分钟）、`2h`（小时）、`1d`（天）。
- **关键点**：`run-time` 包含**爬坡时间 + 稳定运行时间**。

---

### 2. 完整命令示例（最常用模板）

```bash
locust -f my_locustfile.py \
  --headless \
  --users 1000 \
  --spawn-rate 50 \
  --run-time 10m \
  --host https://api.target.com \
  --html report.html
```
**这条命令的执行流程解读：**
1.  **0~20秒**：用户数从 0 线性爬升至 1000（因为 `1000 / 50 = 20秒`）。
2.  **20秒~10分钟**：保持 1000 并发持续施压。
3.  **10分钟整**：自动停止所有用户，聚合统计数据，生成 HTML 报告，进程退出。

### 3. 进阶组合技巧（实战专家视角）

#### A. 结合 `--stop-timeout` 实现优雅退出
默认到达 `run-time` 时会立即强制停止，可能导致正在执行的请求被截断。
- **参数**：`--stop-timeout 30`（给予 30 秒宽限期，等待当前请求和 `on_stop` 执行完毕）。
```bash
locust -f script.py --headless -u 500 -r 20 -t 5m --stop-timeout 30
```

#### B. 分布式场景下的参数分配（Master 控制）
在分布式模式中，`--users` 和 `--spawn-rate` **只需要在 Master 上指定**，Worker 会自动接收并分担压力。
- **Master**：`locust -f script.py --master --headless -u 2000 -r 100 -t 10m`
- **Worker**：`locust -f script.py --worker --master-host=xxx`
- **关键**：每个 Worker 启动的用户数 = `总用户数 / Worker数量`。

#### C. 结合 `--expect-workers` 实现“就绪等待”
在无界面模式下，如果 Master 启动时 Worker 还没连上来，会导致压力达不到目标。
- **解法**：`--expect-workers 4` 会让 Master **等待**直到 4 个 Worker 全部连接成功，才开始计算 `run-time` 并施压。
```bash
locust -f script.py --headless --master --expect-workers=4 -u 2000 -r 50 -t 10m
```

#### D. 退出码控制（CI/CD 判定成败）
无界面模式通常用于自动化流水线（Jenkins/GitLab CI）。我们需要让压测结果告诉 CI 系统“是否通过”。
- **参数**：`--exit-code-on-error`（若有任何请求失败，进程退出码非 0）。
- **更精细**：配合 `--html` 报告，在 `test_stop` 事件中自定义 SLA 校验，并调用 `environment.process_exit_code = 1`。

### 4. 常见陷阱与避坑指南（必读）

| 陷阱现象 | 根因分析 | 解决方案 |
| :--- | :--- | :--- |
| **压测启动很快结束，RPS 未达预期** | `run-time` 设得太短，还没爬完坡就结束了。 | 确保 `run-time` > `users / spawn-rate + 30秒`。 |
| **`--users` 全部分配给了少数 Worker** | 分布式环境下，网络延迟导致部分 Worker 注册较晚。 | 使用 `--expect-workers` 强制等待所有 Worker 就绪。 |
| **测试结束后进程卡死（不退出）** | 存在未关闭的长连接（如 WebSocket），导致 `on_stop` 阻塞。 | 设置 `--stop-timeout 10`，或检查代码中 `on_stop` 是否耗时过长。 |
| **命令行参数报错未被识别** | 在 `headless` 模式下，`--host` 必须显式指定，或代码中定义了 `host` 属性。 | 显式添加 `--host https://xxx`。 |
| **想要观察实时进度但不想开 Web UI** | 无界面模式默认不输出实时统计。 | 增加 `--loglevel INFO` 可以看到周期性的 RPS 摘要，或按 `Ctrl+C` 会显示当前统计。 |

### 5. 快速决策速查表（参数组合逻辑）

| 压测目的 | 参数建议 | 关键考量 |
| :--- | :--- | :--- |
| **冒烟测试（Smoke）** | `-u 10 -r 2 -t 1m` | 快速验证接口连通性，1分钟内跑完。 |
| **容量测试（Capacity）** | `-u 5000 -r 100 -t 30m` | 爬坡 50秒，稳定运行近 30 分钟，观察系统极限。 |
| **稳定性测试（Soak）** | `-u 2000 -r 50 -t 8h` | 长时间运行，需配合 `--stop-timeout` 和磁盘空间监控。 |
| **弹性测试（HPA 验证）** | `-u 1000 -r 5 -t 20m` | 极慢爬坡（200秒爬满），给 K8s 足够的反应时间。 |

---

### 💎 总结
掌握 `--headless` 组合拳，本质上是理解**压测生命周期管理**：
1.  **先定目标**：`--users` 决定压力大小。
2.  **再定节奏**：`--spawn-rate` 决定冲击速度。
3.  **最后定边界**：`--run-time` 决定何时收网。
