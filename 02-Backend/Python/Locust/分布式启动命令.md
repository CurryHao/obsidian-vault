# 分布式启动命令

Locust 的分布式压测是其核心能力之一，通过协调多个工作节点（Worker）来产生巨大的负载。

它的架构非常清晰：一个 **Master** 节点负责调度和汇总，多个 **Worker** 节点负责实际执行压测任务。下面为你详细拆解相关的启动命令和核心参数。

---

### 🚀 核心命令速查

-   **启动 Master 节点**：`locust -f your_locustfile.py --master`
-   **启动 Worker 节点**：`locust -f your_locustfile.py --worker --master-host=<MASTER_IP>`

### 🧠 Master 节点启动参数

Master 是集群的“大脑”，负责调度和统计。

| 参数 | 作用 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| **`--master`** | **以 Master 模式运行** | N/A | **必选**，声明当前节点为 Master。 |
| **`--master-bind-host`** | **Master 绑定的网络接口** | `*` (所有接口) | 指定 Master 监听的 IP 地址。在有多块网卡的机器上，可以指定只监听内网 IP。 |
| **`--master-bind-port`** | **Master 绑定的起始端口** | `5557` | Master 会占用此端口和 `此端口+1` 两个端口（默认 `5557` 和 `5558`）。 |
| **`--expect-workers`** | **期望连接的 Worker 数量** | N/A | 在**无 Web 界面模式**（`--headless`）下使用，Master 会等待指定数量的 Worker 全部连接后，再自动开始测试。 |

### 🛠️ Worker 节点连接参数

Worker 是集群的“肌肉”，负责执行压测任务并上报数据。

| 参数 | 作用 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| **`--worker`** | **以 Worker 模式运行** | N/A | **必选**，声明当前节点为 Worker。 |
| **`--master-host`** | **Master 节点的主机名或 IP** | `127.0.0.1` | Worker 通过此地址连接 Master。 |
| **`--master-port`** | **Master 节点的端口** | `5557` | Worker 通过此端口连接 Master。 |

### 💻 完整启动示例

**1. 在 Master 机器上执行：**
```bash
locust -f your_locustfile.py --master
```
这会在 `0.0.0.0:8089` 启动 Web 界面，并在 `0.0.0.0:5557` 和 `5558` 监听 Worker 的连接。

**2. 在每台 Worker 机器上执行：**
```bash
locust -f your_locustfile.py --worker --master-host=192.168.1.100
```
*   假设 Master 的 IP 是 `192.168.1.100`，Worker 会连接到 Master 的 `5557` 端口。

> **注意**：所有机器（Master 和 Worker）都必须有**完全相同**的 `locustfile.py` 文件。

### ❓ 常见问题与排查

**1. Worker 连接不上 Master？**
*   **检查网络与防火墙**：确保 Worker 能 `ping` 通 Master 的 IP，且防火墙允许 `5557` 和 `5558` 端口的 TCP 通信。
*   **检查 `--master-bind-host`**：如果 Master 启动时指定了 `--master-bind-host=127.0.0.1`，它只会监听本地回环地址，导致其他机器无法连接。分布式场景下通常不指定此参数，或绑定到内网 IP。

**2. 需要注意什么？**
*   **多核利用**：为了充分利用 CPU，建议在每个 Worker 节点上，为每个 CPU 核心启动一个 Worker 进程。
*   **文件同步**：确保 `locustfile.py` 在 Master 和所有 Worker 上完全一致。
*   **无 Web 界面模式**：结合 `--headless` 和 `--expect-workers` 参数，可以实现自动化分布式压测。

### 💎 总结

掌握这些命令是进行大规模分布式压测的第一步，核心操作可以概括为：

1.  **Master**：使用 `--master` 启动。
2.  **Worker**：使用 `--worker --master-host <MASTER_IP>` 启动。

通过灵活组合这些参数，你就能构建起一个强大的分布式压测集群。
