# 请求拦截器与预处理钩子

请求拦截器（Interceptor）与预处理钩子（Pre-processing Hooks）是 Locust 中实现**非侵入式横切关注点**（Cross-Cutting Concerns）的核心机制。它们让你能在不修改 `@task` 业务代码的前提下，统一处理认证注入、请求日志、失败重试、自定义统计等通用逻辑。

---

### 1. 概念对比：拦截器 vs. 钩子

| 维度 | **拦截器（Interceptor）** | **预处理钩子（Pre-processing Hook）** |
| :--- | :--- | :--- |
| **触发时机** | **请求执行前/后**，包裹具体请求 | **请求执行前**，仅做前置处理 |
| **控制能力** | 可**修改请求参数**、**中断请求**、**重试** | 只能**读取或修改请求参数**，不能中断 |
| **作用范围** | 通常绑定到**特定客户端**（如 gRPC Stub） | **全局**（通过 `events` 事件监听） |
| **典型场景** | gRPC 元数据注入、HTTP 请求签名、统一超时设置 | 全局日志记录、请求头标准化、统计上报 |
| **实现方式** | 继承客户端框架的拦截器接口（如 `grpc.ClientInterceptor`） | 使用 Locust 的 `@events.request.add_listener` |

---

### 2. 原生支持：`@events.request` 请求监听器（预处理钩子）

这是 Locust **最常用**的全局钩子，在每次请求完成后触发，可用于记录、修改或过滤统计数据。

```python
from locust import events

# ===== 全局请求前置处理（修改参数） =====
@events.request.add_listener
def on_request(request_type, name, response_time, response_length, response, exception, context, **kwargs):
    """每次请求完成后执行（不支持中断请求）"""
    if exception:
        print(f"[ERROR] {name} 失败: {exception}")
    
    # 可以修改统计上下文（如动态调整 name）
    # 注意：无法修改已发出的请求本身

# ===== 更精细的预处理：使用 Session 级别的钩子 =====
class MyUser(HttpUser):
    def on_start(self):
        # 在用户级别设置请求拦截（通过 mock client 方法）
        original_get = self.client.get
        
        def wrapped_get(url, **kwargs):
            # 请求前置处理：注入追踪 ID
            if 'headers' not in kwargs:
                kwargs['headers'] = {}
            kwargs['headers']['X-Trace-Id'] = f"trace_{self.user_id}"
            # 调用原始方法
            return original_get(url, **kwargs)
        
        self.client.get = wrapped_get
```
```code**局限性**：`@events.request` 是**事后**触发，无法在请求前修改参数或中断请求。

### 3. 高级拦截器：自定义客户端包装（HTTP）

如果你需要**请求级预处理**（如统一签名、自动重试），推荐包装 `self.client` 的方法。

```python
class SmartUser(HttpUser):
    def on_start(self):
        # 包装 client.get 方法
        original_get = self.client.get
        
        def get_with_retry(url, **kwargs):
            max_retries = kwargs.pop('retries', 3)
            for attempt in range(max_retries):
                resp = original_get(url, **kwargs)
                if resp.status_code < 500:
                    return resp
                # 服务端错误，等待后重试
                gevent.sleep(2 ** attempt)
            return resp  # 返回最后一次失败结果
        
        self.client.get = get_with_retry
    
    @task
    def unstable_api(self):
        # 自动带有重试能力
        self.client.get("/unstable", retries=3)
```

### 4. gRPC 拦截器（官方集成方案）

gRPC 原生支持 `ClientInterceptor`，是压测中最常见的拦截器应用场景。**核心价值**：自动上报 RPC 耗时到 Locust 统计，业务代码零侵入。

```python
import time
import grpc
from locust import events

# ===== 实现 gRPC 统计拦截器 =====
class LocustStatsInterceptor(grpc.UnaryUnaryClientInterceptor):
    def __init__(self, environment):
        self.environment = environment

    def intercept_unary_unary(self, continuation, client_call_details, request):
        start = time.perf_counter()
        exception = None
        try:
            response = continuation(client_call_details, request)
            return response
        except Exception as e:
            exception = e
            raise
        finally:
            response_time = (time.perf_counter() - start) * 1000
            # 上报到 Locust 统计系统
            events.request.fire(
                request_type="GRPC",
                name=client_call_details.method,  # 方法名
                response_time=response_time,
                response_length=0,
                exception=exception,
                context={}
            )

# ===== 在 User 中注册拦截器 =====
class GrpcUser(User):
    abstract = True
    
    def __init__(self, environment):
        super().__init__(environment)
        # 启用 gevent 兼容
        import grpc.experimental.gevent as grpc_gevent
        grpc_gevent.init_gevent()
        
        # 创建带拦截器的 Channel
        interceptor = LocustStatsInterceptor(environment)
        self.channel = grpc.intercept_channel(
            grpc.insecure_channel(self.host),
            interceptor
        )
        # 初始化 Stub
        self.stub = MyServiceStub(self.channel)
    
    def on_stop(self):
        self.channel.close()

# ===== 业务代码完全不受影响 =====
class MyGrpcUser(GrpcUser):
    @task
    def get_data(self):
        # 拦截器自动统计此次调用的耗时
        self.stub.GetData(GetDataRequest(id=1))
```

### 5. 实战：组合模式（预处理 + 后处理）

有时需要**前置注入 Token**，**后置校验业务码**。可以通过组合 `on_start` + 拦截器实现。

```python
class AdvancedUser(HttpUser):
    def on_start(self):
        # 前置：获取 Token 并注入到 Headers
        resp = self.client.post("/auth", json={"user": "test"})
        self.token = resp.json()["access_token"]
        self.client.headers.update({"Authorization": f"Bearer {self.token}"})
        
        # 拦截器：包装 post 方法进行业务码校验
        original_post = self.client.post
        
        def post_with_biz_check(url, **kwargs):
            with original_post(url, catch_response=True, **kwargs) as resp:
                if resp.status_code == 200:
                    biz_code = resp.json().get("code")
                    if biz_code != 0:
                        resp.failure(f"业务码错误: {biz_code}")
                return resp
        
        self.client.post = post_with_biz_check
    
    @task
    def order(self):
        # 自动带有 Token + 业务码校验
        self.client.post("/order", json={"product": "book"})
```

### 6. 关键陷阱与避坑指南

| 陷阱 | 现象 | 解决方案 |
| :--- | :--- | :--- |
| **拦截器内再次触发事件** | 造成 `events.request` 死循环 | 在拦截器中设置标志位（如 `_in_interceptor = True`）避免递归。 |
| **gRPC 拦截器未启用 gevent 兼容** | 请求阻塞整个进程 | 务必在创建 Channel **之前**执行 `grpc.experimental.gevent.init_gevent()`。 |
| **包装方法导致类型提示丢失** | IDE 无法自动补全 | 使用 `functools.wraps(original_get)` 保留元数据。 |
| **拦截器内长时间阻塞** | 拖慢所有协程 | 拦截器中**禁止**执行 I/O 或 `time.sleep`，仅做轻量计算。 |
| **修改 `client.headers` 后未合并** | 请求级 Headers 覆盖全局 | 理解优先级：请求级 > 会话级。若需合并，手动 `headers.update(self.client.headers)`。 |

---

### 7. 快速选型决策表

| 需求场景 | 推荐方案 |
| :--- | :--- |
| **全局日志/统计**（不改请求） | `@events.request` 监听器 |
| **HTTP 统一加 Header** | `on_start` 中设置 `self.client.headers` |
| **HTTP 统一签名/重试** | 包装 `self.client.get/post` 方法 |
| **gRPC 统一统计/元数据注入** | 实现 `grpc.ClientInterceptor` |
| **WebSocket 消息过滤** | 在 `WebSocketClient` 的 `send` 方法中包装 |
| **按用户类型动态修改超时** | `on_start` 中设置 `self.client.timeout` |

---

### 💎 总结

- **预处理钩子（`@events.request`）**：适合**全局统计**和**轻量日志**，但无法修改请求。
- **拦截器**：通过**包装客户端方法**或**框架原生接口**，实现**请求级细粒度控制**，是生产级压测脚本的标准实践。
- **黄金法则**：拦截器**必须保持轻量**（微秒级执行），任何可能阻塞的操作（如网络请求）必须移至 `on_start` 或 `@task` 内部。

如果你需要实现**自定义协议的拦截器**（如 MQTT、数据库连接），核心思路是**在客户端的 `send`/`execute` 方法外层包裹统计逻辑**，这和我们包装 HTTP `get` 方法的原理完全一致。你目前打算拦截哪种协议？我可以给出更具体的代码模板。
