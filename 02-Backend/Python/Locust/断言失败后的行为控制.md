# 断言失败后的行为控制

在 Locust 中，断言失败（如 `response.failure()`）默认**不会停止用户**，也不会中断测试流程。这种设计是基于**统计完整性**的考量——即使某个请求失败了，用户也应当继续模拟后续行为，以真实反映业务场景。

但你完全可以根据业务严重性，自主控制失败后的行为，在**继续执行**、**停止当前用户**、**重试请求**或**直接终止整个测试**之间自由选择。

---

### 1. 默认行为：继续执行（Continue）

使用 `response.failure()` 时，当前请求被标记为失败并计入统计，但**用户会立即执行下一个任务**（遵循 `wait_time` 逻辑）。

```python
@task
def browse(self):
    with self.client.get("/product", catch_response=True) as resp:
        if resp.status_code != 200:
            resp.failure("页面加载失败")
            # 函数执行完毕，用户继续执行后续任务
        # 即使失败，也继续执行此处的后续逻辑
```
**适用场景**：非关键路径失败（如推荐商品加载失败），不影响核心下单流程。

---
### 2. 停止当前用户（Stop User）

当遇到致命错误（如登录失败、Token无效），后续任务毫无意义时，应**立即销毁当前用户协程**，释放资源。

- **方案 A：抛出 `StopUser` 异常（推荐）**
  框架会优雅地终止该用户，调用 `on_stop()` 钩子，并停止孵化该用户的新任务。

```python
from locust.exception import StopUser

@task
def login(self):
    with self.client.post("/auth", json={"user": "test"}, catch_response=True) as resp:
        if resp.status_code != 200:
            resp.failure("登录失败")
            raise StopUser()  # 用户终止，释放协程
        # 登录成功，继续执行
```

- **方案 B：抛出 `AssertionError`（慎用）**
  虽然也能终止用户，但异常会记入 **Exceptions** 而非 **Failures**，且不会触发 `on_stop`，**不推荐**用于业务断言。

---

### 3. 退出当前任务集（Interrupt TaskSet）

如果失败仅影响当前**子流程**（如购物车结算失败），但用户仍可返回主流程继续浏览，使用 `self.interrupt()` 退出当前 `TaskSet`，回到父级任务池。

```python
class CheckoutFlow(SequentialTaskSet):
    @task
    def step_pay(self):
        with self.client.post("/pay", catch_response=True) as resp:
            if resp.json().get("balance") < 0:
                resp.failure("余额不足，跳过支付流程")
                self.interrupt()  # 跳出当前 SequentialTaskSet，返回主浏览任务
                return
            # 正常支付逻辑...
```

### 4. 自动重试（Retry）机制

Locust 本身**不内置**自动重试，但你可以通过编程轻松实现。推荐两种模式：

#### A. 简单循环重试（同步阻塞式）
适用于幂等接口（如查询状态）。

```python
@task
def query_status(self):
    max_retries = 3
    for attempt in range(1, max_retries + 1):
        with self.client.get("/status", catch_response=True, timeout=5) as resp:
            if resp.status_code == 200:
                # 成功则立即标记成功并退出循环
                resp.success()
                return
            # 失败时记录，但不立即调用 failure()
            if attempt < max_retries:
                gevent.sleep(2 ** attempt)  # 退避等待 2s, 4s
        # 若所有重试均失败，在循环外统一标记最终失败
    # 循环结束未返回，说明全部失败
    with self.client.get("/status", catch_response=True) as final_resp:
        final_resp.failure("重试 3 次后仍失败")
```

#### B. 使用装饰器封装重试逻辑（可复用）
创建通用重试装饰器，侵入性小。

```python
import functools
from locust.exception import StopUser

def retry_on_failure(max_retries=3, delay=1, stop_on_fatal=True):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(self, *args, **kwargs):
            last_exception = None
            for attempt in range(1, max_retries + 1):
                try:
                    return func(self, *args, **kwargs)
                except AssertionError as e:
                    last_exception = e
                    if attempt < max_retries:
                        gevent.sleep(delay * attempt)
                        continue
                    else:
                        if stop_on_fatal:
                            # 如果希望终止用户
                            raise StopUser(f"重试失败: {e}")
                        else:
                            # 只记录失败，继续执行
                            self.environment.events.request.fire(exception=e, ...)
        return wrapper
    return decorator

# 使用
@task
@retry_on_failure(max_retries=3)
def flaky_api(self):
    with self.client.get("/unstable", catch_response=True) as resp:
        if resp.status_code != 200:
            # 抛出自定义异常，触发重试
            raise AssertionError(f"状态码异常: {resp.status_code}")
        resp.success()
```

### 5. 基于错误类型的智能策略（失败分类）

根据不同的失败原因，采取不同的控制策略：

```python
@task
def smart_request(self):
    try:
        with self.client.post("/order", json={...}, catch_response=True, timeout=5) as resp:
            data = resp.json()
            if data.get("code") == 1001:  # 库存不足
                resp.failure("库存不足，跳过该用户")
                raise StopUser()  # 无法继续，销毁用户
            elif data.get("code") == 1002:  # 系统繁忙，可重试
                resp.failure("系统繁忙")
                gevent.sleep(1)
                # 递归调用自身（需注意防止无限递归）
                return self.smart_request()
            else:
                resp.success()
    except TimeoutError:
        # 网络超时，标记失败但继续执行其他任务
        pass
```

### 6. 全局控制：终止整个测试（Fail Fast）

如果你的压测目标是验证系统是否满足 SLA，一旦**全局失败率**超过阈值（如 5%），应立即停止整个测试，避免无效压测。

- **方式一**：使用 `--exit-code-on-error` 参数，只要有任何失败，测试结束时进程退出码非 0（适用于 CI/CD）。
- **方式二**：编写 `@events.test_start` 监听器，通过 `environment.runner.quit()` 直接终止。

```python
@events.request.add_listener
def on_request(exception, **kwargs):
    if exception:
        # 获取当前环境
        env = kwargs.get('environment')
        if env and env.runner:
            stats = env.runner.stats
            total = stats.total.num_requests
            failures = stats.total.num_failures
            if total > 100 and (failures / total) > 0.05:  # 失败率超5%
                print("失败率超阈值，强制终止测试！")
                env.runner.quit()  # 立即退出所有 Worker
```

### 7. 决策速查表

| 业务场景 | 推荐策略 | 代码方式 |
| :--- | :--- | :--- |
| **非关键信息加载失败**（如广告位） | **继续执行**，仅记录失败 | `response.failure()` |
| **登录/鉴权失败** | **停止当前用户** | `raise StopUser()` |
| **购物车结算失败**，但用户还能浏览 | **退出当前 TaskSet** | `self.interrupt()` |
| **服务器返回 5xx 或超时（临时故障）** | **重试 3 次** | 循环/装饰器 + `gevent.sleep` |
| **业务返回“库存为 0”（明确不可恢复）** | **停止用户** | `raise StopUser()` |
| **CI/CD 流水线 - 失败率过高** | **终止整个测试** | `env.runner.quit()` |
| **调试阶段**（希望看到完整栈信息） | **抛异常** | `raise AssertionError` |

---

### 💎 核心原则

1.  **默认安全**：`response.failure()` 是**统计性**的，不影响流程。
2.  **显式控制**：只有当你主动 `raise StopUser` 或 `self.interrupt` 时，流程才会改变。
3.  **重试需谨慎**：永远要设置**最大重试次数**和**退避间隔**，否则在服务故障时，重试风暴会迅速耗尽压测机资源。
4.  **分布式一致性**：在 Master-Worker 模式下，`StopUser` 和 `interrupt` 仅在当前 Worker 的当前协程生效，不影响其他 Worker。

掌握这些控制手段后，你的压测脚本就具备了生产级的**鲁棒性**——既能精准记录业务失败，又能弹性处理各种异常，确保压测过程稳定可控。如果你需要实现**基于响应头 `Retry-After` 的智能重试**，或想了解**如何将重试次数作为自定义统计指标**，可以告诉我，我们继续深入。
