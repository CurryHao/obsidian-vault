# 标签过滤选择性执行

`--tags` 和 `--exclude-tags` 是 Locust 命令行中用于**精准控制测试范围**的过滤参数。它们允许你在不修改代码的前提下，灵活选择只运行“冒烟测试”或排除“慢速接口”，是 CI/CD 流水线中实现测试分层（Smoke Test / Full Test）的核心工具。

---

### 1. 核心原理：`@tag` 装饰器

在脚本中，使用 `@tag` 装饰器为任务打上标签（支持多个标签）。

```python
# locustfile.py
from locust import HttpUser, task, tag

class MyUser(HttpUser):
    
    @tag("smoke")  # 仅打标 smoke
    @task
    def health_check(self):
        self.client.get("/health")

    @tag("smoke", "critical")  # 同时打标 smoke 和 critical
    @task
    def login(self):
        self.client.post("/login")

    @tag("critical", "slow")   # 打标 critical 和 slow
    @task
    def report(self):
        self.client.get("/heavy_report")

    @task  # 无标签
    def index(self):
        self.client.get("/")
```


### 2. 命令行过滤逻辑（关键）

#### A. 只运行包含特定标签（`--tags`）
只运行带有指定标签的任务（**逻辑或 OR**，只要包含其中一个即执行）。

```bash
# 只执行带有 "smoke" 标签的任务
locust -f locustfile.py --tags smoke
# 执行: health_check, login (index 无标签，不执行)

# 执行带有 "smoke" 或 "critical" 标签的任务
locust -f locustfile.py --tags smoke critical
# 执行: health_check, login, report (index 依然不执行)
```

#### B. 排除包含特定标签（`--exclude-tags`）
排除所有带有指定标签的任务（**逻辑或 OR**，只要包含其中一个即被排除）。

```bash
# 不执行任何带有 "slow" 标签的任务
locust -f locustfile.py --exclude-tags slow
# 执行: health_check, login, index (report 被排除)
```

#### C. 组合使用（交集筛选）
当 `--tags` 和 `--exclude-tags` **同时使用**时，任务必须满足：**（包含 `--tags` 中的任意标签）且（不包含 `--exclude-tags` 中的任意标签）**。

```bash
# 执行带有 critical，但不带有 slow 的任务
locust -f locustfile.py --tags critical --exclude-tags slow
# 执行: login (login 有 critical，且没有 slow)
# 不执行: report (有 critical，但也有 slow，被排除)
# 不执行: health_check (没有 critical)
```

---

### 3. 无标签任务的行为准则（重要）

- **不指定 `--tags` 时**：所有任务（包括无标签任务）均被执行。
- **指定了 `--tags` 时**：**无标签任务默认不会被执行**，除非你显式地给它们添加了标签，或在命令中未使用 `--tags`。

> **实战技巧**：如果你希望无标签任务作为“兜底”任务执行，可以给它们打上一个通用标签（如 `@tag("default")`），然后在流水线中根据情况包含或排除该标签。

---

### 4. 分布式场景下的注意事项

- **Master 控制**：`--tags` 和 `--exclude-tags` 参数**仅在 Master 节点启动时生效**，Worker 会自动继承过滤规则，无需在每个 Worker 上重复配置。
- **Web UI 联动**：在 Web UI 模式下，`--tags` 依然生效。你可以在启动时预过滤，然后在界面中点击“Start”只启动过滤后的用户类。

---

### 5. 进阶用法：类级别的标签继承

`@tag` 不仅可以加在方法上，还可以加在 `User` 类上（Locust 2.x+）。当类级别存在标签时，该类下**所有任务**自动继承该标签。

```python
@tag("v2", "beta")
class NewApiUser(HttpUser):
    @task
    def v2_home(self):
        self.client.get("/v2/home")
    
    @task
    def v2_order(self):
        self.client.post("/v2/order")
```

此时，`--tags v2` 会同时执行 `v2_home` 和 `v2_order`，无需在每个方法上重复打标。

---

### 6. 实战场景速查表

| 场景描述 | 推荐命令 | 效果 |
| :--- | :--- | :--- |
| **流水线冒烟测试**（只跑核心接口） | `--tags smoke` | 只执行标记了 `@tag("smoke")` 的任务。 |
| **全量压测，但排除慢查询接口** | `--exclude-tags slow heavy` | 排除标记了 `slow` 或 `heavy` 的接口。 |
| **压测新版本功能，但排除已知 BUG 接口** | `--tags new_feature --exclude-tags buggy` | 只测新功能，但有 BUG 的接口不测。 |
| **无过滤，全量执行** | 不加 `--tags` 或 `--exclude-tags` | 所有 `@task` 均执行。 |

### 7. 常见陷阱

| 陷阱 | 现象 | 解决方案 |
| :--- | :--- | :--- |
| **标签拼写错误** | 命令看起来没问题，但任务就是不执行。 | 检查 `@tag` 和命令行的字符串是否完全一致（大小写敏感）。 |
| **误以为 `--tags` 是精确匹配** | 使用了 `--tags critical slow`，以为只执行同时包含两个标签的任务。 | 记住 `--tags` 是 **OR** 关系。若要精确组合，请使用 `--tags critical --exclude-tags slow`。 |
| **无标签任务被忽略** | 指定 `--tags smoke` 后，未标记的方法没有执行。 | 这是预期行为。若不想如此，需给所有方法显式打标。 |

### 💎 总结

- `--tags`：白名单（包含即执行）。
- `--exclude-tags`：黑名单（包含即排除）。
- **组合逻辑**：`（包含 A 或 B）且（不包含 C 或 D）`。
- **核心价值**：让你用**一套脚本**应对**多种测试场景**（开发自测、CI冒烟、全量压测），无需维护多个脚本文件。
