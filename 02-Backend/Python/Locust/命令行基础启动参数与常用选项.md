# 命令行基础启动参数与常用选项

Locust 的**命令行接口（CLI）** 是控制其所有行为的核心入口。通过组合不同的参数，你可以灵活地切换运行模式、控制负载并管理结果输出。

下面我将 Locust 的命令行参数分为几大类，并逐一说明其用途。你也可以随时在终端输入 `locust --help` 查看完整列表。

### 🎯 核心与脚本配置

| 参数 | 说明 | 示例 |
| :--- | :--- | :--- |
| `-f, --locustfile` | **指定测试脚本文件**。可以是单个 `.py` 文件、一个包含多个文件的目录，或用逗号分隔的多个文件。 | `locust -f my_test.py`<br>`locust -f locustfiles/`<br>`locust -f file1.py,file2.py` |
| `-H, --host` | **指定目标测试系统的URL**。这是压测请求发送的基础地址。 | `locust -H https://www.example.com` |
| `-u, --users` | **设置目标并发用户数**。通常与`--headless`或`--autostart`配合使用。 | `locust --headless -u 1000` |

### 🚀 运行模式与负载控制

| 参数 | 说明 | 示例 |
| :--- | :--- | :--- |
| `--headless` | **无Web界面模式**。启动后立即开始测试，适合集成到CI/CD等自动化流程。 | `locust -f my_test.py --headless -u 100 -r 10` |
| `--autostart` | **自动开始测试**。与`--headless`类似，但**会保留Web界面**，方便你实时查看统计数据。 | `locust -f my_test.py --autostart -u 100 -r 10` |
| `-r, --spawn-rate` | **用户孵化速率**，即每秒启动的用户数。 | `locust --headless -u 1000 -r 100` |
| `-t, --run-time` | **测试运行时长**。时间到了之后会自动停止。格式如：`10s`, `1m`, `2h`等。 | `locust --headless -t 1h30m` |
| `--stop-timeout` | **优雅停止超时**。在测试结束时，等待正在执行的任务完成的最大秒数，避免任务被强制中断。 | `locust --headless --run-time 10m --stop-timeout 60` |

### 🌐 分布式压测参数

| 参数 | 说明 | 示例 |
| :--- | :--- | :--- |
| `--master` | **以Master模式启动**。Master节点负责调度和汇总结果，不执行压测任务。 | `locust -f my_test.py --master` |
| `--worker` | **以Worker模式启动**。Worker节点执行实际的压测任务，并连接到Master。 | `locust -f my_test.py --worker --master-host=192.168.1.10` |
| `--expect-workers` | **在无界面模式下，指定期望连接的Worker数量**。Master会等待所有Worker就绪后才开始测试。 | `locust -f my_test.py --headless --master --expect-workers=5` |

### 📊 报告与日志

| 参数 | 说明 | 示例 |
| :--- | :--- | :--- |
| `--html` | **生成HTML格式的测试报告**。 | `locust --headless --html=report.html` |
| `--csv` | **以CSV格式保存统计数据**。会生成多个文件，如`[前缀]_stats.csv`等。 | `locust --headless --csv=results` |
| `--loglevel` | **设置日志级别**。可选值：`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`。 | `locust --loglevel=WARNING` |
| `--logfile` | **将日志输出到指定文件**，而非控制台。 | `locust --logfile=locust.log` |

### 🛠️ 高级与辅助选项

| 参数 | 说明 | 示例 |
| :--- | :--- | :--- |
| `--web-host` | **绑定Web界面的网络接口**。默认`*`（所有接口）。 | `locust --web-host=127.0.0.1` |
| `-P, --web-port` | **指定Web界面的端口**。默认`8089`。 | `locust --web-port=8090` |
| `--class-picker` | **在Web界面启用User类和Shape类的选择器**，方便在运行时切换。 | `locust -f locustfiles/ --class-picker` |
| `--config` | **指定配置文件**（`.conf`），可以批量设置参数。 | `locust --config=my.conf` |
| `--exit-code-on-error` | **如果测试出现错误，设置进程的退出码为非0**，便于CI/CD识别失败。 | `locust --headless --exit-code-on-error` |
| `-l, --list` | **列出当前Locustfile中所有的User类**。 | `locust -l` |

### 💡 实际应用场景示例

*   **日常开发调试（带Web界面）**：
    ```bash
    locust -f my_test.py -H https://dev-api.example.com
    ```
    启动后，访问 `http://localhost:8089` 在Web界面上手动设置用户数和启动测试。

*   **CI/CD 流水线集成（无界面模式）**：
    ```bash
    locust -f my_test.py --headless -u 100 -r 10 -t 5m --host=https://staging-api.example.com --html=report.html --csv=results
    ```

*   **分布式压测（Master节点）**：
    ```bash
    # 在Master机器上执行
    locust -f my_test.py --master --expect-workers=4 --headless -u 1000 -r 100 -t 30m
    ```

*   **分布式压测（Worker节点）**：
    ```bash
    # 在每台Worker机器上执行
    locust -f my_test.py --worker --master-host=<MASTER_IP>
    ```

### ⚙️ 配置方式：三管齐下

除了命令行，Locust 还支持另外两种配置方式，它们有明确的优先级（后面的会覆盖前面的）：

1.  **配置文件**：默认读取 `~/.locust.conf` 和 `./locust.conf`。
2.  **环境变量**：以 `LOCUST_` 为前缀的大写变量名。
3.  **命令行参数**：**优先级最高**，会覆盖前两者。

掌握这些参数，你就能灵活地将 Locust 集成到各种开发和运维流程中。
