# 自定义统计数据聚合与事件上报扩展

在 Locust 中，内置的统计（RPS、响应时间、HTTP 状态码）是针对**协议请求**维度的。但在实际压测中，我们往往更关心**业务指标**，例如：**“成功下单数”**、**“库存扣减失败数”**、**“支付回调超时数”**。

为了实现自定义业务指标聚合，并让它们在 Master-Worker 分布式环境下全局生效，有**三种主流扩展方案**。下面为你逐一拆解。

---

### 1. 方案一：本地聚合 + `test_stop` 输出（简单，仅单机）

适用于单节点运行，或只需看 Worker 本地日志的场景。直接在 `events.request` 中更新全局变量。

```python
from locust import events
from locust.runners import WorkerRunner

# 自定义业务计数（使用普通变量，注意协程安全）
custom_metrics = {
    "checkout_success": 0,
    "inventory_shortage": 0,
}

@events.request.add_listener
def on_request(exception, name, response_time, **kwargs):
    # 假设 name 中包含特定业务标识
    if "checkout" in name and exception is None:
        custom_metrics["checkout_success"] += 1
    if exception and "库存不足" in str(exception):
        custom_metrics["inventory_shortage"] += 1

@events.test_stop.add_listener
def on_stop(environment, **kwargs):
    print(f"业务汇总: {custom_metrics}")
    
```

---

### 2. 方案二：使用官方社区的 `locust_plugins`（轻量级扩展）

社区库 `locust-plugins` 提供了 `CustomMetrics` 类，它能将自定义指标**挂载到 Locust 的统计引擎中**，使其出现在 Web UI 的 Statistics 表格里（作为额外行），并支持 `--csv` 导出。

**安装**：
```bash
pip install locust-plugins
```

**代码实现**：
```python
from locust import HttpUser, task
from locust_plugins.listeners import CustomMetrics

# 1. 定义自定义指标类
metrics = CustomMetrics(
    checkout_success={"unit": "count"},
    inventory_shortage={"unit": "count"},
)

class MyUser(HttpUser):
    @task
    def buy(self):
        with self.client.post("/order", catch_response=True) as resp:
            if resp.json().get("code") == 0:
                # 2. 标记成功（自动递增 checkout_success）
                metrics.checkout_success += 1
                resp.success()
            elif resp.json().get("code") == 1001:
                # 3. 标记失败（自动递增 inventory_shortage）
                metrics.inventory_shortage += 1
                resp.failure("库存不足")
```

**效果**：
- Web UI 的 `Statistics` 表格底部会多出 `checkout_success` 和 `inventory_shortage` 两行。
- **分布式支持**：Worker 会自动将增量发送给 Master 进行聚合，无需额外代码。

---

### 3. 方案三：原生 Master-Worker 自定义消息（生产级硬核）

如果你的指标结构复杂（如多维 Map），或不想引入第三方库，可以通过 Locust 的**自定义事件消息**实现 Worker 到 Master 的数据同步。

#### A. Worker 端：收集并上报
```python
from locust import events
from locust.runners import WorkerRunner

# 本地暂存
local_biz_stats = {"total_orders": 0, "total_revenue": 0.0}

@events.request.add_listener
def on_request(exception, name, **kwargs):
    if "pay" in name and exception is None:
        local_biz_stats["total_orders"] += 1
        # 模拟金额累加（需从响应中提取）
        # local_biz_stats["total_revenue"] += 100.0

@events.report_to_master.add_listener
def on_report_to_master(environment, **kwargs):
    """Worker 在发送常规统计数据时，顺便捎上自定义指标"""
    # 注意：此钩子会频繁调用（默认 3 秒一次）
    return {"biz_stats": local_biz_stats.copy()}
```

#### B. Master 端：聚合接收
```python
from locust import events
from locust.runners import MasterRunner

# Master 全局聚合器
global_biz_stats = {"total_orders": 0, "total_revenue": 0.0}

@events.worker_report.add_listener
def on_worker_report(environment, client_id, data, **kwargs):
    """Master 收到 Worker 上报时触发"""
    if isinstance(environment.runner, MasterRunner):
        worker_stats = data.get("biz_stats", {})
        global_biz_stats["total_orders"] += worker_stats.get("total_orders", 0)
        global_biz_stats["total_revenue"] += worker_stats.get("total_revenue", 0.0)

@events.test_stop.add_listener
def on_test_stop(environment, **kwargs):
    if isinstance(environment.runner, MasterRunner):
        print(f"🏆 最终业务汇总: {global_biz_stats}")
        # 可写入文件或数据库
```

> **关键点**：`report_to_master` 会随心跳频繁触发，确保返回的数据是**轻量级字典**，避免序列化大对象造成网络阻塞。

### 4. 方案四：直接推送至外部时序数据库（云原生最佳实践）

在 K8s + Prometheus 时代，将指标直接暴露给监控系统，比塞在 Locust 内存里更具可观测性。

**集成 Prometheus**（使用 `prometheus_client`）：
```python
from prometheus_client import Counter, Gauge, push_to_gateway

# 定义业务指标（需安装 prometheus-client）
biz_success = Counter('locust_biz_success', 'Business success count', ['api'])
biz_fail = Counter('locust_biz_fail', 'Business failure count', ['reason'])

@events.request.add_listener
def push_to_prom(exception, name, **kwargs):
    if "order" in name:
        if exception is None:
            biz_success.labels(api='order').inc()
        else:
            biz_fail.labels(reason='timeout').inc()

@events.test_stop.add_listener
def push_on_stop(**kwargs):
    push_to_gateway('localhost:9091', job='locust_test', registry=registry)
```

**集成 InfluxDB（批量写入）**：
利用 `@events.request` 做缓存队列，`@events.test_start` 启动后台协程定时 Flush，避免高频插入拖垮数据库（代码较长，此处简述）。

### 5. 选型对比与决策表

| 方案 | 分布式聚合 | Web UI 可见 | 外部存储 | 侵入性 | 推荐场景 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **本地变量** | ❌ | ❌ | 仅控制台 | 低 | 快速调试单机脚本 |
| **locust_plugins** | ✅ | ✅ (表格行) | CSV | 低 | 团队日常压测，想看业务趋势 |
| **原生自定义消息** | ✅ | ❌ (需日志) | 需自写 | 中 | 复杂聚合逻辑（如多维哈希表） |
| **Prometheus/InfluxDB** | ✅ | Grafana 展示 | 是 | 中 | 生产环境长期监控、告警联动 |

---

### 6. 核心避坑指南（高能预警）

1.  **线程/协程安全**：Locust 基于 `gevent`（单线程多协程），普通 `+= 1` 操作是**安全的**（没有 GIL 竞争）。但如果涉及 `dict` 的 `update`，建议使用 `gevent.lock.Semaphore` 锁保护。
2.  **性能损耗**：`events.request` 回调在**每次请求后同步执行**。若在其中做复杂 JSON 解析或写数据库，会严重拖慢整体 RPS。请务必**保持回调函数轻量**（< 1ms）。
3.  **自定义消息序列化**：`report_to_master` 的数据会通过 `msgpack` 序列化。请确保字典中的值都是**基础类型**（int, float, str），不要携带 `Response` 对象或不可序列化的自定义类。
4.  **Master 内存膨胀**：若你在 Master 端累加所有 Worker 的明细数据（如存储每个请求的金额），长时间运行会导致 Master OOM。**只做增量聚合**（`+=`），不存储明细。

---

### 💎 最终建议

- **若要快速验证业务指标**：直接上 `locust_plugins` 的 `CustomMetrics`，5 分钟搞定聚合和 Web 展示。
- **若企业已有 Grafana/Prometheus**：走推送网关方案，将业务指标与系统指标（CPU/Mem）绘制在同一张仪表盘，实现**全链路关联分析**。
- **若追求绝对代码纯净**：使用原生自定义消息（方案三），这是 Locust 官方设计预留的扩展口，最灵活。
