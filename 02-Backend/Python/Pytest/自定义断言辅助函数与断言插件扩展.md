# 自定义断言辅助函数与断言插件扩展

## 📌 一句话总结
> 在PyTest生态中，**断言辅助函数**与**断言插件扩展**是将测试代码从“重复性校验”进化为“领域专属语言（DSL）”的关键工具。它们让你能够：

*   **封装复杂的断言逻辑**（如深度比较JSON、忽略无关字段）。
*   **提供语义化的错误信息**（如“用户订单状态应为‘已完成’，实际为‘待支付’”）。
*   **为特定数据类型定制差异报告**（如为Pandas DataFrame生成结构化比较）。

我将从**简单辅助函数**、**利用`pytest.fail`提供丰富错误**、**编写`pytest_assertrepr_compare`钩子**以及**打包为插件**四个层次，逐步指导你构建专业的断言扩展。

## 🎯 核心概念

### 1. 简单辅助函数：封装重复逻辑

当你需要在多个测试中执行相同的断言（如校验JSON Schema、比较时间戳范围），可以将其抽取为普通函数。但**必须使用`pytest.fail`或显式抛出`AssertionError`，并附带清晰的错误信息**，因为`assert`在辅助函数中**不会被PyTest重写**（重写仅作用于测试模块）。

```python
# assert_helpers.py
import pytest
from datetime import datetime, timedelta

def assert_time_within_range(actual: datetime, expected: datetime, tolerance_seconds: int = 5):
    """断言实际时间在期望时间的前后 tolerance 秒内"""
    diff = abs((actual - expected).total_seconds())
    if diff > tolerance_seconds:
        pytest.fail(
            f"时间超出允许范围: 实际 {actual.isoformat()}, "
            f"期望 {expected.isoformat()}, "
            f"差值 {diff:.2f} 秒 > {tolerance_seconds} 秒"
        )

# 在测试中使用
def test_timestamp():
    start = datetime.now()
    result = generate_timestamp()
    assert_time_within_range(result, start, tolerance_seconds=2)
```

**关键点**：
- 使用`pytest.fail`（它内部会抛出`Failed`异常）明确失败原因。
- 提供详细的上下文信息（实际值、期望值、容忍度），避免开发时再去排查。

### 2. 利用`pytest.raises`和`pytest.warns`的参数化

你也可以创建**上下文管理器风格的断言**，模仿`pytest.raises`的API，用于验证副作用或状态变化。

```python
from contextlib import contextmanager

@contextmanager
def assert_event_emitted(emitter, event_type):
    """断言某个事件发射器在代码块内发射了指定类型的事件"""
    events_before = emitter._events.copy()
    try:
        yield
    finally:
        events_after = emitter._events
        new_events = [e for e in events_after if e not in events_before]
        if not any(e.type == event_type for e in new_events):
            pytest.fail(f"未发射期望的事件类型: {event_type}，实际新事件: {[e.type for e in new_events]}")
```

```python
def test_button_click():
    emitter = EventEmitter()
    with assert_event_emitted(emitter, "click"):
        button.click()  # 若未触发 "click" 事件，测试失败
```

### 3. 高级扩展：`pytest_assertrepr_compare` 钩子

这是PyTest提供的最强大的断言定制钩子。当内置比较（`==`、`!=`、`<`等）失败时，你可以**拦截**并返回自定义的多行比较报告。

**经典场景**：为`pandas.DataFrame`或`numpy.ndarray`生成差异摘要，而非打印整个巨大对象。

```python
# conftest.py 或 插件模块
import numpy as np
import pytest

def pytest_assertrepr_compare(op, left, right):
    """为 numpy 数组提供定制的比较报告"""
    if op == "==" and isinstance(left, np.ndarray) and isinstance(right, np.ndarray):
        # 如果数组完全相等，返回 None 让框架继续默认处理（不会触发此钩子，但以防万一）
        if np.array_equal(left, right):
            return None
        
        # 找出差异位置
        diff = left != right
        diff_indices = np.where(diff)
        # 准备输出行
        lines = [
            "numpy 数组比较失败:",
            f"  形状: 左 {left.shape} vs 右 {right.shape}",
            f"  差异元素数量: {np.sum(diff)}",
        ]
        # 显示前5个差异
        num_diff = min(5, np.sum(diff))
        for i in range(num_diff):
            idx = tuple(coord[i] for coord in diff_indices)
            lines.append(f"  位置 {idx}: 左 {left[idx]} vs 右 {right[idx]}")
        
        if np.sum(diff) > 5:
            lines.append(f"  ... 以及 {np.sum(diff)-5} 个其他差异")
        
        return lines
    return None  # 退回默认处理
```

**效果**：当`assert np.array_equal(arr1, arr2)`失败时，输出将不再是满屏的数组打印，而是简洁的差异摘要。

### 4. 创建自定义断言插件（可复用）

当你的自定义断言逻辑变得通用（如团队内多个项目需要），可以将其打包为PyTest插件。插件的核心是在`conftest.py`中实现钩子，或通过`pytest_plugins`公开。

**插件目录结构**：
```python
pytest_assert_custom/
├── __init__.py
├── plugin.py          # 包含钩子实现
└── helpers.py         # 辅助函数
```

**`plugin.py`**：
```python
import pytest
from .helpers import assert_time_within_range  # 即使未直接使用钩子，也可提供

def pytest_assertrepr_compare(config, op, left, right):
    # 实现自定义比较（如对自定义类）
    if op == "==" and hasattr(left, "_custom_eq"):
        # 返回自定义错误消息
        ...
    return None
```

**通过`setuptools`安装**后，只需在`pyproject.toml`中注册插件：
```toml
[project.entry-points.pytest11]
assert_custom = "pytest_assert_custom.plugin"
```
用户安装插件后，即可自动获得自定义断言行为。

### 5. 编写断言辅助函数时的“关键陷阱”

| 陷阱 | 错误示例 | 正确做法 |
| :--- | :--- | :--- |
| **在辅助函数中使用`assert`但期望失败信息被增强** | `def assert_contains(container, item): assert item in container` | **失败时信息贫乏**（仅`AssertionError`）。必须使用`pytest.fail(f"容器中没有 {item}，实际为 {container}")`。 |
| **忘记处理多行错误消息** | `pytest.fail("错误")` | 推荐返回多行字符串，其中第一行作为概要，后续行提供细节。 |
| **`pytest_assertrepr_compare`返回的行格式错误** | 返回字符串列表，但未以`[“概要”, “详情1”, “详情2”]`格式。 | 第一行应为简要描述，后续行为详细上下文。 |
| **钩子未保留默认行为** | 钩子未返回`None`，导致某些比较无法处理。 | **重要**：若条件不满足，必须`return None`让PyTest使用默认报告。 |

### 6. 何时选择哪种方式？

| 需求 | 推荐方案 | 复杂度 |
| :--- | :--- | :--- |
| 封装单个测试内的重复断言 | 简单辅助函数 + `pytest.fail` | 低 |
| 为特定数据类型（如DataFrame）提供专属比较报告 | `pytest_assertrepr_compare` 钩子 | 中 |
| 跨多个项目共享断言逻辑 | 打包为PyTest插件，注册钩子和辅助函数 | 高 |
| 需要类似`assert_that`风格的流畅接口 | 自定义类 + `__call__` 或 `pytest` 插件（可参考`assertpy`或`hamcrest`） | 中-高 |

### 7. 范例：实现一个“忽略字典中某字段”的断言辅助

```python
def assert_dict_equal_ignoring_keys(actual, expected, ignore_keys):
    """断言两个字典相等，但忽略指定的键"""
    filtered_actual = {k: v for k, v in actual.items() if k not in ignore_keys}
    filtered_expected = {k: v for k, v in expected.items() if k not in ignore_keys}
    if filtered_actual != filtered_expected:
        # 使用 pytest.fail 并提供差异
        diff_keys = set(filtered_actual.keys()) ^ set(filtered_expected.keys())
        common_keys = set(filtered_actual.keys()) & set(filtered_expected.keys())
        diff_values = {k: (filtered_actual.get(k), filtered_expected.get(k)) 
                       for k in common_keys if filtered_actual[k] != filtered_expected[k]}
        pytest.fail(
            f"过滤后的字典不相等 (忽略键: {ignore_keys})\n"
            f"  额外键: {diff_keys}\n"
            f"  值不同的键: {diff_values}"
        )
```
