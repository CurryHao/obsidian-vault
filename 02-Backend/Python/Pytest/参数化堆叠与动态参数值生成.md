# 参数化堆叠与动态参数值生成

## 📌 一句话总结
> 这是参数化机制的“终极形态”。你已掌握堆叠（笛卡尔积）和间接（`indirect`），现在我们将突破“静态列表”的限制，进入**运行时动态生成参数**的领域。

动态参数生成的本质是：**在测试收集阶段（而非编码阶段）决定测试用例的组合与数量**。它让测试套件能够根据外部环境（文件内容、数据库查询、API响应）或复杂逻辑动态膨胀或收缩。

我将从“轻量级动态”到“重量级钩子”分层拆解，并直面**“交叉依赖组合”**这一核心痛点。

## 🎯 核心概念

### 1. 轻量级动态：在装饰器内调用函数（收集时执行）

这是最安全、最简单的动态方式。参数列表由函数在**模块加载时**生成。

```python
import pytest
import json

# 动态生成参数列表：从外部JSON文件读取
def load_test_cases():
    with open("test_data.json", "r") as f:
        data = json.load(f)
    # 返回列表，每个元素是一组参数
    return [(item["input"], item["expected"]) for item in data]

# 装饰器内部直接调用函数，生成列表
@pytest.mark.parametrize("input_val, expected", load_test_cases())
def test_from_json(input_val, expected):
    assert input_val * 2 == expected
```
**特点**：代码简洁，但参数在`pytest`收集时一次性固定。若JSON文件改变，需重启`pytest`。

### 2. 中级动态：堆叠时的“条件过滤”（笛卡尔积取子集）

当你堆叠装饰器时，默认生成全排列（笛卡尔积）。但很多时候，某些组合是**非法或无效**的（例如`OS="Windows"`且`Python_Version="3.6"`可能不兼容）。我们可以在堆叠后用**列表推导式展开，再压缩回pytest参数**，实现“带过滤的笛卡尔积”。

```python
import pytest

# 定义两个维度的有效值
os_list = ["Windows", "Linux"]
python_versions = ["3.8", "3.9", "3.10"]

# 定义有效组合规则（仅当OS为Windows时，Python版本可为3.8）
valid_combinations = [
    (os_, py) for os_ in os_list for py in python_versions
    if not (os_ == "Windows" and py == "3.8")  # 过滤掉 Windows + 3.8
]

@pytest.mark.parametrize("os_type, py_ver", valid_combinations)
def test_cross_platform(os_type, py_ver):
    print(f"Testing {os_type} with Python {py_ver}")
    # 实际生成了 (2 * 3) - 1 = 5 个用例，而非 6 个
```
**注意**：这种方法失去了`ids`自动拼接的便利性，但获得了组合的精准控制权。

### 3. 高级动态：`pytest_generate_tests` 钩子（终极程序化控制）

这是`pytest`提供的**参数化元编程钩子**。它允许你在收集阶段遍历每一个测试节点，并根据**自定义标记（Marker）**或**函数签名**，以编程方式注入参数。

**适用场景**：动态参数依赖于命令行选项（如`--env=prod`）、外部服务（如读取数据库配置表）或复杂的业务规则。

#### 实战：根据命令行参数动态决定测试数据源
```python
# conftest.py
import pytest

def pytest_addoption(parser):
    parser.addoption("--data-source", action="store", default="local", 
                     help="数据源: local 或 remote")

def pytest_generate_tests(metafunc):
    """钩子：为每个测试函数动态生成参数"""
    # 1. 检查测试函数是否标记了 'dynamic_data' 标记
    if 'dynamic_data' in metafunc.fixturenames:
        # 2. 获取命令行参数
        data_source = metafunc.config.getoption("--data-source")
        
        if data_source == "local":
            params = [{"id": 1, "name": "Local_Alice"}, {"id": 2, "name": "Local_Bob"}]
        else:  # remote
            # 模拟从远程API拉取数据
            params = [{"id": 100, "name": "Remote_Charlie"}]
        
        # 3. 核心：将参数列表注入到名为 'dynamic_data' 的参数中
        # 同时为每个用例生成有意义的 ID
        metafunc.parametrize(
            "dynamic_data",  # 必须与测试函数的参数名一致
            params, 
            ids=[p["name"] for p in params],
            scope="function"  # 安全起见，保持 function 作用域
        )

# test_dynamic.py
import pytest

# 无需写 @parametrize！钩子会根据命令行参数动态注入
def test_dynamic_example(dynamic_data):
    print(f"Running with: {dynamic_data}")
    assert dynamic_data["id"] > 0
```
**执行效果**：
- `pytest --data-source=local` → 运行2个用例（Local_Alice, Local_Bob）
- `pytest --data-source=remote` → 运行1个用例（Remote_Charlie）

### 4. 动态参数的“交叉依赖”处理（`metafunc` 的自省能力）

当函数有多个参数，且只想动态生成其中一个，而其他参数保持静态时，`metafunc`可以精准识别签名：

```python
def pytest_generate_tests(metafunc):
    # 检查测试函数是否有 'env' 参数
    if 'env' in metafunc.fixturenames:
        # 根据当前测试所在模块名动态决定环境
        if "prod" in metafunc.module.__name__:
            env_list = ["production"]
        else:
            env_list = ["dev", "staging"]
        metafunc.parametrize("env", env_list, scope="function")
```

### 5. 极易踩中的 3 个深度陷阱

| 陷阱现象 | 根本原因 | 解决方案 |
| :--- | :--- | :--- |
| **动态生成参数导致收集阶段极慢（CI超时）** | `pytest_generate_tests` 中调用了慢速数据库或网络API，且未做缓存 | 在钩子中实现**LRU缓存**（`@lru_cache`），或提前将数据导出为本地JSON，测试收集阶段只读本地文件 |
| **`metafunc.parametrize` 与装饰器 `@parametrize` 同时使用导致重复参数** | 钩子和装饰器都尝试为同一参数赋值，引发冲突或覆盖 | **二选一**：要么纯装饰器，要么纯钩子。若需混合，在钩子中检查 `metafunc.definition` 是否已有参数，如有则跳过 |
| **动态生成的用例 ID 重复导致收集警告** | 动态生成参数时，`ids`列表生成了重复字符串 | 在 `ids` 生成逻辑中加入**计数后缀**，如 `f"{name}_{idx}"`，确保全局唯一 |

### 6. 决策矩阵：三种动态方案的取舍

| 动态程度 | 推荐方案 | 适用场景 | 可维护性 |
| :--- | :--- | :--- | :--- |
| **静态数据变换**（如读取JSON文件） | 装饰器内调用函数（方案1） | 测试数据独立于环境，只需一次读取 | 高（逻辑集中） |
| **组合过滤**（剔除无效配对） | 列表推导式生成组合列表（方案2） | 多维度矩阵测试，但部分组合非法 | 中（需手动维护过滤逻辑） |
| **高度动态**（依赖命令行、外部API、复杂策略） | **`pytest_generate_tests` 钩子（方案3）** | 多环境切换、动态数据源、基于硬件的参数调整 | 低（需懂钩子机制，但最灵活） |

### 7. 终极实战：动态 ID + 参数化堆叠 + 标记注入

你可以在 `pytest_generate_tests` 中为每个动态生成的用例附加不同的标记（Marker）：

```python
def pytest_generate_tests(metafunc):
    if "config" in metafunc.fixturenames:
        params = [
            pytest.param({"env": "dev"}, id="dev", marks=pytest.mark.smoke),
            pytest.param({"env": "prod"}, id="prod", marks=pytest.mark.slow),
        ]
        metafunc.parametrize("config", params)
```
这样，执行 `pytest -m smoke` 将精准命中 `dev` 用例，实现了**动态数据与动态标记的绑定**。

您现在的需求是**多环境配置切换**（如dev/staging/prod），还是**基于外部数据源动态生成测试矩阵**？告诉我具体的动态源（文件、数据库、API或命令行选项），我可以为您提供一段`pytest_generate_tests`的完整模板，包含缓存和异常处理，确保您的测试收集速度不会被打断。
