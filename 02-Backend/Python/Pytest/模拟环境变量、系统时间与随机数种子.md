# 模拟环境变量、系统时间与随机数种子

## 📌 一句话总结
> 这是测试中**三大不确定性源头**的终极解决方案。环境变量、系统时间、随机数生成器——它们共同构成了“不可控依赖”的铁三角。如果不能将它们驯服，你的测试就会变得随机失败（Flaky）或依赖特定运行环境。

我将为你提供一套从**内置工具**到**专用第三方库**的分层模拟策略，并揭示时区、种子重置等极易踩中的陷阱。

## 🎯 核心概念

### 1. 模拟环境变量：`monkeypatch` 的“主场”

环境变量是跨进程的全局状态，必须**隔离**。`monkeypatch` 提供了最安全、最简洁的操作。

#### 核心 API
```python
import os
import pytest

def test_env_variables(monkeypatch):
    # 1. 设置环境变量（测试结束后自动恢复原值或删除）
    monkeypatch.setenv("API_KEY", "test-secret-123")
    monkeypatch.setenv("APP_MODE", "debug")
    
    # 2. 删除环境变量（模拟未定义状态）
    monkeypatch.delenv("DATABASE_URL", raising=False)  # raising=False 防止变量不存在时报错
    
    # 3. 验证
    assert os.getenv("API_KEY") == "test-secret-123"
    assert os.getenv("DATABASE_URL") is None
```

#### 高阶技巧：`prepend` 和 `append` 修改 PATH 类变量
```python
def test_modify_path(monkeypatch):
    # 在 PATH 前面追加目录（不影响现有路径）
    monkeypatch.setenv("PATH", "/my/custom/bin", prepend=os.pathsep)
    assert os.getenv("PATH").startswith("/my/custom/bin")
```

**致命陷阱**：永远**不要**直接修改 `os.environ` 字典而不在 `teardown` 中恢复，因为环境变量是进程全局的，会污染后续测试。**必须**使用 `monkeypatch` 自动恢复机制。

### 2. 模拟系统时间：`freezegun` vs `monkeypatch`

模拟时间是测试**时效性逻辑**（如过期判断、定时任务、报表生成）的唯一可靠方式。有两种方案：

#### 方案一：专用库 `freezegun`（强烈推荐，工业标准）
`freezegun` 能够**全局冻结**所有 `datetime`、`time` 模块的调用，且支持时间旅行（Tick）。

```python
# 安装: pip install freezegun
from freezegun import freeze_time
import datetime
import pytest

# 1. 装饰器模式：冻结在特定时间
@freeze_time("2025-01-01 12:00:00")
def test_expired_token():
    token = generate_token(expire_minutes=30)
    # 此时 datetime.now() 始终返回 2025-01-01 12:00:00
    assert token.is_expired() is False

# 2. 上下文管理器模式（更灵活，可内嵌在测试中）
def test_with_time_travel():
    with freeze_time("2025-01-01 10:00:00") as frozen_time:
        # 执行逻辑...
        frozen_time.tick(delta=datetime.timedelta(minutes=10))  # 快进 10 分钟
        # 当前时间变为 10:10
        assert is_business_hours() is True
```

#### 方案二：手动 `monkeypatch`（轻量，无需第三方库）
如果不想引入额外依赖，可以手动替换 `datetime.datetime.now`。

```python
import datetime

def test_manual_freeze(monkeypatch):
    class FakeDateTime:
        @classmethod
        def now(cls):
            return datetime.datetime(2025, 1, 1, 12, 0, 0)
    
    # 注意：要 patch 被测模块中引用的位置
    monkeypatch.setattr("my_module.datetime.datetime", FakeDateTime)
    
    # 但注意：这会 patch 整个 datetime.datetime 类，可能导致其他方法（如 fromtimestamp）失效。
    # 更精准的做法是仅 patch now 方法，但 Python 的 C 扩展限制较多，故首选 freezegun。
```

**抉择建议**：在需要**断言时间差**或**连续 tick**的场景，`freezegun` 是必选；若仅需一个固定的静态时间戳，用 `monkeypatch` 即可。

### 3. 模拟随机数种子：`random.seed` vs `mocker.patch`

随机数测试的目标是**保证每次运行得到相同的结果**，从而让测试稳定。有两种策略：

#### 策略一：固定种子（适用于使用 `random` 模块）
在测试或 fixture 中调用 `random.seed(42)`，保证伪随机序列一致。

```python
import random
import pytest

@pytest.fixture(autouse=True)
def set_random_seed():
    """所有测试自动使用固定种子"""
    random.seed(42)
    yield
    # 无需恢复，后续测试依然使用固定种子；若需完全隔离，可在此处 random.seed(None) 重置

def test_random_shuffle():
    data = [1, 2, 3, 4, 5]
    random.shuffle(data)
    # 每次运行，data 的顺序都是 [3, 5, 1, 4, 2] (固定)
    assert data == [3, 5, 1, 4, 2]
```

#### 策略二：Mock 具体随机函数（适用于只关心特定返回值）
若被测逻辑只调用了 `random.randint` 或 `random.choice`，直接 Mock 返回值比固定种子更精准。

```python
def test_random_choice(mocker):
    # 强制 random.choice 永远返回 "rock"
    mocker.patch("my_module.random.choice", return_value="rock")
    
    result = play_rps()  # 内部调用 random.choice(["rock","paper","scissors"])
    assert result == "rock"
    
def test_random_randint(mocker):
    # 强制 random.randint(1, 10) 永远返回 7
    mocker.patch("my_module.random.randint", return_value=7)
    assert roll_dice() == 7
```

#### 策略三：使用 `numpy.random` 时的处理
如果项目使用 NumPy，需要分别设置 `np.random.seed(42)`，因为它有自己的随机数生成器状态。

```python
import numpy as np

@pytest.fixture(autouse=True)
def set_numpy_seed():
    np.random.seed(42)
```

### 4. 组合实战：三剑合璧

假设我们测试一个**根据当前时间和随机数生成唯一邀请码**的函数：

```python
import os, random, datetime, hashlib

def generate_invite_code(user_id):
    salt = os.getenv("INVITE_SALT", "default_salt")
    seed = random.randint(1000, 9999)
    timestamp = datetime.datetime.now().strftime("%Y%m%d")
    raw = f"{user_id}-{salt}-{seed}-{timestamp}"
    return hashlib.md5(raw.encode()).hexdigest()[:8]
```

**完整测试（隔离全部三个依赖）**：
```python
from freezegun import freeze_time
import pytest

@freeze_time("2025-06-01 12:00:00")
def test_generate_invite_code(monkeypatch, mocker):
    # 1. 模拟环境变量
    monkeypatch.setenv("INVITE_SALT", "test_salt")
    
    # 2. 模拟随机数（固定返回 1234）
    mocker.patch("my_module.random.randint", return_value=1234)
    
    # 3. 执行（时间已被 freezegun 冻结）
    code = generate_invite_code(1001)
    
    # 4. 预期：基于固定输入计算 (1001-test_salt-1234-20250601)
    assert code == "d3b07384"  # 预先算好的 MD5 前缀
```

### 5. 极易踩中的 3 个致命陷阱

| 陷阱现象 | 根本原因 | 解决方案 |
| :--- | :--- | :--- |
| **`freezegun` 未覆盖 `time.time()` 导致部分依赖时间戳的库行为异常** | `freezegun` 默认只 patch `datetime`，某些 C 扩展库直接调用 `time.time()`。 | 使用 `freeze_time(..., tick=True)` 让时间流逝，或同时 Mock `time.time`：`mocker.patch('time.time', return_value=... )` |
| **固定种子 `random.seed(42)` 后，多个测试互相影响** | 种子是全局状态，测试 A 修改了随机序列位置，测试 B 基于种子拿到的值变了 | 在 `conftest.py` 中使用 `autouse` fixture，并在 **yield 后执行 `random.seed(None)`** 重置状态，或每个测试单独设置种子 |
| **`monkeypatch.setenv` 后，`os.getenv` 获取不到值** | 在测试函数内修改环境变量，但被测模块在 **import 阶段**就已经读取了环境变量（全局变量），Patch 发生得太晚 | **延迟加载（Lazy Loading）**：在被测函数内部调用 `os.getenv`，而非模块顶层赋值；或在测试中 **重新导入** 被测模块（`importlib.reload`） |

### 6. 终极决策矩阵

| 控制对象 | 简单场景（推荐） | 复杂场景（跨多个时间点） | 完全隔离方案（无需第三方） |
| :--- | :--- | :--- | :--- |
| **环境变量** | `monkeypatch.setenv` | `monkeypatch.setenv` (多个变量) | 直接 `os.environ` 并手动恢复（不推荐） |
| **系统时间** | `freezegun` 装饰器 | `freezegun` 上下文 + `.tick()` | 手动 `monkeypatch` 替换 `datetime.now`（极易出错） |
| **随机数** | `mocker.patch('random.randint', return_value=x)` | `random.seed(42)` + 精确序列控制 | 实现自己的 `Random` 包装类并用 `monkeypatch` 替换 |
