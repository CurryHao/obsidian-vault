# 基于标记的条件执行与过滤筛选

## 📌 一句话总结
> 这是PyTest作为“测试调度器”的核心能力——**通过标记（Markers）在收集阶段就完成测试集的动态裁剪**。这与`skipif`（运行时跳过）有本质区别：`-m`过滤是在测试**执行之前**就将未匹配的用例直接剔除，连收集列表都不进入，更高效、更干净。

我将从**命令行表达式语法**、**组合过滤策略**、**编程式动态过滤**以及**CI流水线实战**四个维度，彻底讲透这套筛选机制。

## 🎯 核心概念

### 1. 命令行表达式：`-m` 的布尔运算逻辑

`-m` 参数支持 `and`、`or`、`not` 以及圆括号 `()` 来控制优先级。**解析顺序遵循Python的布尔运算规则**：`not` > `and` > `or`。

| 表达式 | 语义（筛选条件） | 常用场景 |
| :--- | :--- | :--- |
| `-m "smoke"` | 包含 `smoke` 标记的所有用例 | PR快速门禁 |
| `-m "not slow"` | **排除**所有含 `slow` 标记的用例 | 本地开发，剔除耗时长尾 |
| `-m "smoke or integration"` | 包含 `smoke` **或** `integration` 任一标记 | CI的集成测试阶段 |
| `-m "smoke and not slow"` | 必须含 `smoke`，且**不能**含 `slow` | 确保冒烟用例一定是快的 |
| `-m "(unit or integration) and not flaky"` | 单元或集成，但排除不稳定用例 | 稳定回归集 |

**执行验证命令**（不执行，仅查看哪些会被选中）：
```bash
pytest --collect-only -m "smoke and (not slow)"
```

### 2. 组合过滤：`-m` + `-k` + `--lf` 的叠加效应

这三种筛选机制是 **`AND`（交集）** 关系，层层收紧。

| 参数组合 | 筛选逻辑 | 最终结果 |
| :--- | :--- | :--- |
| `-m smoke -k "login"` | 标记含 `smoke` **且** 名称含 `login` | 只跑冒烟测试中与登录相关的用例 |
| `-m "not slow" --lf` | 标记不含 `slow` **且** 上次执行失败的 | 修复上次失败的快速用例（排除慢速失败，节约时间） |
| `-m integration -x` | 标记含 `integration`，遇到**第一个失败立即停止** | 快速定位集成环境的首个断点 |

**优先级说明**：`pytest` 先按 `-k` 筛选名称，再按 `-m` 筛选标记，最后应用 `--lf`，但逻辑上是严苛的交集。

### 3. 高级编程过滤：`pytest_collection_modifyitems` 动态“踢出”用例

当命令行的布尔逻辑无法满足复杂业务规则时（如“根据当前环境变量决定是否运行某些标记的用例”），可以在 `conftest.py` 中**编程式移除或跳过**用例。

**场景**：当环境变量 `SKIP_INTEGRATION=true` 时，将所有含 `integration` 标记的用例动态标记为 `skip`。

```python
# conftest.py
import os
import pytest

def pytest_collection_modifyitems(config, items):
    # 1. 读取外部环境变量
    skip_integration = os.getenv("SKIP_INTEGRATION", "false").lower() == "true"
    
    if skip_integration:
        # 2. 遍历所有收集到的测试节点
        for item in items:
            # 检查该测试是否包含 'integration' 标记
            if item.get_closest_marker("integration"):
                # 3. 动态添加 skip 标记（运行时跳过，但依然会在收集列表中显示为 SKIPPED）
                item.add_marker(pytest.mark.skip(reason="环境变量 SKIP_INTEGRATION 已设置"))
```

**对比 `-m "not integration"`**：前者直接不收集（`collected 0 items`），后者收集但显示 `SKIPPED`。如果外部条件是在**执行阶段**才确定的（如依赖服务启动失败），用编程式 `skip` 更合适，因为测试节点依然会被统计在总数中，便于CI报告计数。

### 4. 基于标记的“测试套件（Test Suite）”预设

如果有一组固定的筛选逻辑需要反复使用，可以在 `pyproject.toml` 中预设 `addopts`，但更推荐**利用 `conftest.py` 的 `pytest_addoption` 自定义参数**，封装成“套件别名”。

```python
# conftest.py
def pytest_addoption(parser):
    parser.addoption(
        "--suite", action="store", default="fast", 
        choices=["fast", "full", "smoke_only"],
        help="预设测试套件: fast(快速), full(全量), smoke_only(仅冒烟)"
    )

def pytest_collection_modifyitems(config, items):
    suite = config.getoption("--suite")
    if suite == "fast":
        # 动态剔除 slow 和 integration
        skip_cond = pytest.mark.skip(reason="快速套件模式下剔除")
        for item in items:
            if item.get_closest_marker("slow") or item.get_closest_marker("integration"):
                item.add_marker(skip_cond)
    elif suite == "smoke_only":
        # 只保留 smoke，剔除其他所有
        for item in items[:]:  # 遍历副本
            if not item.get_closest_marker("smoke"):
                items.remove(item)  # 直接从集合中移除（收集阶段剔除）
```

**执行命令**：
```bash
pytest --suite=smoke_only  # 等价于复杂的布尔表达式，但更语义化
```

### 5. 极易踩中的 3 个致命陷阱

| 陷阱现象 | 根本原因 | 解决方案 |
| :--- | :--- | :--- |
| **`-m "not slow and integration"` 意外排除了所有用例** | 运算符优先级：`not` > `and`，实际解析为 `(not slow) and integration`。若一个用例是 `integration` 但同时有 `slow`，则 `not slow` 为 False，整个表达式为 False。 | 使用显式括号：`-m "integration and not slow"` 或 `-m "not (slow and integration)"` 取决于本意 |
| **Windows 终端中 `-m "smoke or integration"` 报错** | Windows CMD/PowerShell 对双引号和管道符解析不同 | 在 Windows PowerShell 中使用单引号：`-m 'smoke or integration'`；或使用 `--` 分隔：`pytest -- -m "smoke or integration"` |
| **`pytest_collection_modifyitems` 中直接 `del items[:]` 导致崩溃** | 修改列表时破坏了内部索引 | 若想清空，使用 `items.clear()`；若想移除部分，**必须反向迭代**或**拷贝遍历**（如 `for item in items.copy():`） |

### 6. CI 流水线中的典型分层策略

| CI 阶段 | 推荐命令 | 超时要求 | 失败处理 |
| :--- | :--- | :--- | :--- |
| **PR 快速检查（<3min）** | `pytest -m "smoke or unit" -n auto --maxfail=2` | 5分钟 | 立即失败，阻断合并 |
| **Staging 集成验证** | `pytest -m "integration and not slow" --tb=short` | 15分钟 | 失败阻断，但允许重试一次 |
| **夜间全量回归** | `pytest -m "integration or slow or e2e" -n auto --dist=loadscope` | 2小时 | 结果仅通知，不阻断发布（异步分析） |
| **本地开发默认** | 在 `pyproject.toml` 中设置 `addopts = ["-m", "not (slow or integration)"]` | 无限制 | 开发者自行判断 |

### 7. 终极诊断命令

```bash
# 查看当前表达式会选中哪些测试（不执行）
pytest --collect-only -m "your_complex_expression"

# 显示每个测试被选中/跳过的详细原因（调试利器）
pytest -v -rs  # -rs 显示 skip 原因
pytest --collect-only -q  # 简洁列表，快速计数
```
