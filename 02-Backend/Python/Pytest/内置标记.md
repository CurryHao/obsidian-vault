# 内置标记

## 📌 一句话总结
> 这是PyTest内置标记体系的**“行为控制四剑客”**。它们不参与业务逻辑验证，而是专门用于**控制测试的执行流**：哪些该跑、哪些该跳、哪些该预期失败、哪些该挂载固件。

我将这四种标记分为“**跳转控制**”（skip/xfail）和“**资源挂载**”（usefixtures）两大类，并为你揭示`strict`参数与`condition`求值时机的致命细节。

## 🎯 核心概念

### 1. `@pytest.mark.skip` 与 `@pytest.mark.skipif`：条件性忽略

**核心语义**：**完全跳过**该测试，不执行Setup，不执行Test，不执行Teardown。统计结果中记为 `SKIPPED`。

| 标记 | 适用场景 | 语法 |
| :--- | :--- | :--- |
| **`skip`** | 无条件跳过（如功能未实现、环境永久缺失） | `@pytest.mark.skip(reason="尚未实现")` |
| **`skipif`** | 满足条件时跳过（如依赖库未安装、Python版本过低、操作系统不匹配） | `@pytest.mark.skipif(sys.version_info < (3,10), reason="需要Python 3.10+")` |

**实战示例**：
```python
import sys
import pytest

# 无条件跳过
@pytest.mark.skip(reason="该功能将在 v2.0 重构后启用")
def test_legacy_feature():
    assert False  # 不会执行

# 条件跳过：仅在 Windows 下跳过（Linux/Mac 正常执行）
@pytest.mark.skipif(sys.platform == "win32", reason="Windows 下此测试不稳定")
def test_unix_specific():
    assert True

# 跳过整个类（所有方法均被跳过）
@pytest.mark.skipif(not HAS_CUDA, reason="GPU 不可用")
class TestGPUAcceleration:
    def test_kernel(self): pass
    def test_memory(self): pass
```

### 2. `@pytest.mark.xfail`：预期失败（标记为 XFAIL）

**核心语义**：**执行该测试**，但预期它会失败。这是一种“占位符”机制，用于管理已知缺陷或边缘情况。

- **若测试失败** → 记为 `XFAIL`（预期失败，测试套件视为**通过**，不会中断CI）。
- **若测试意外成功** → 记为 `XPASS`（意外通过，默认视为通过，但会发出警告）。

#### `strict` 参数（极其重要）
- `strict=False`（默认）：`XPASS` 仅警告，不改变整体测试结果（绿）。
- `strict=True`：将 `XPASS` **视为失败（FAILED）**。**强烈建议生产环境开启**，防止“原本预期失败但已修复”的测试被默默忽略。

```python
import pytest

# 基础用法：预期因除零而失败
@pytest.mark.xfail(raises=ZeroDivisionError, reason="已知除零 Bug #123")
def test_divide_by_zero():
    1 / 0  # 抛出 ZeroDivisionError → XFAIL (通过)

# strict=True 模式：若该 Bug 修复了（不抛异常），则直接 FAILED 提醒你删除标记
@pytest.mark.xfail(strict=True, reason="等待修复完成后删除此标记")
def test_fixed_bug():
    assert 2 + 2 == 4  # 若此断言通过 → XPASS → 因 strict=True 转为 FAILED
```

**典型使用场景**：
1.  **新功能开发中**：先写测试，再写实现（TDD），此时标记为 `xfail`。
2.  **第三方依赖的已知缺陷**：上游依赖未修复，但我们不想阻塞CI。
3.  **极难复现的边缘崩溃**：记录下来，定期运行以确认是否被意外修复。

### 3. `@pytest.mark.usefixtures`：静默挂载固件

**核心语义**：**不需要接收返回值**，仅为了触发固件的Setup和Teardown副作用（如重置缓存、切换目录、加载环境变量）。

与直接在参数中声明Fixtures的区别：
- **参数注入**：`def test(db_conn):` → 需要拿到对象。
- **`usefixtures`**：`@pytest.mark.usefixtures("reset_state")` → 只关心固件的“动作”，不关心其返回。

**经典场景**：自动事务回滚、监控日志启动、临时的环境变量注入。

```python
import pytest

@pytest.fixture
def clean_redis_cache():
    """清理Redis缓存（不返回任何值）"""
    print("清空Redis")
    yield
    print("恢复Redis")

# 应用于单个测试
@pytest.mark.usefixtures("clean_redis_cache")
def test_rate_limiter():
    # 执行时，Redis 已清空（Setup），测试结束后自动恢复（Teardown）
    assert rate_limiter.check("user_1") is True

# 应用于整个类（所有方法均挂载该固件）
@pytest.mark.usefixtures("clean_redis_cache", "reset_db")
class TestBatchJobs:
    def test_job_1(self): pass
    def test_job_2(self): pass
```

> **与 `autouse=True` 的抉择**：`usefixtures` 是**显式声明**，可读性强；`autouse` 是**隐式全局**，适合基础设施（如日志）。优先使用 `usefixtures` 提升代码可维护性。

### 4. 命令行联动：精准控制标记集合

虽然 `skip`/`xfail` 是内置逻辑，但你依然可以用 `-m` 结合自定义标记来**组合筛选**：

```bash
# 运行所有非跳过的测试（即排除 skip 和 skipif 标记的）
pytest -m "not skip"

# 但注意：xfail 不会被 -m 跳过，它依然会执行。若想排除 xfail，需结合自定义标记策略。
```

### 5. 极易踩中的 3 个致命陷阱

| 陷阱现象 | 根本原因 | 解决方案 |
| :--- | :--- | :--- |
| **`skipif` 的条件在收集阶段求值，而不是运行阶段** | 如果条件依赖动态数据（如数据库读取），该数据在收集时可能尚未准备好 | 将动态判断逻辑封装在 Fixture 中，使用 `pytest.skip()` 在 Fixture 内部**运行时**主动跳过 |
| **误将 `xfail` 当作 `skip` 使用** | 认为 `xfail` 不会执行代码。实际上它会**完整执行**，只是结果分类不同 | 若代码根本不能跑（如导入错误），必须用 `skip`；`xfail` 用于“能跑但失败”的场景 |
| **`XPASS` 悄无声息地污染了回归测试** | 某 Bug 被修复后，`xfail` 测试通过，但开发者未收到通知，导致该用例永久处于灰色地带 | 在 `pyproject.toml` 中全局设置 `xfail_strict = true`，将所有 `XPASS` 强制转为 `FAILED`，倒逼团队及时清理过期的 `xfail` 标记 |

### 6. 终极速查对比表

| 标记 | 是否执行代码 | 统计结果 | `strict` 影响 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **`skip` / `skipif`** | ❌ **不执行** | `SKIPPED` | 无 | 环境不满足、功能下线 |
| **`xfail`** (失败) | ✅ **执行** | `XFAIL` (通过) | 无，本身就是通过 | 已知缺陷、TDD占位 |
| **`xfail`** (成功) | ✅ **执行** | `XPASS` (警告) | `True` 时变为 **FAILED** | **强烈建议设为 True**，强制清理旧标记 |
| **`usefixtures`** | ✅ 执行固件动作 | 不影响结果（依赖内部断言） | 无 | 挂载副作用固件，不关心返回值 |

### 7. 在 Fixture 中主动跳过（替代 `skipif` 的高级技巧）

当跳过条件依赖于 Fixture 构造过程中的资源时，在 Fixture 内部调用 `pytest.skip()`：

```python
@pytest.fixture
def only_if_admin_config():
    config = load_config()
    if config["role"] != "admin":
        pytest.skip("当前配置非管理员模式，跳过该测试")
    return config

def test_admin_feature(only_if_admin_config):
    # 只有管理员配置下才会执行
    assert only_if_admin_config["level"] == 10
```

您现在是否遇到**某个测试在特定环境下老失败**（如 CI 与本地不一致），需要加入条件跳过？或者**有大量遗留的 `xfail` 标记需要清理**？告诉我具体痛点，我可以为您制定一套 **“标记审计策略”**（如用 `pytest --collect-only -m xfail` 查看所有预期失败的用例），并指导您在 CI 中开启 `xfail_strict` 来强制回归。您想从哪个场景开始？
