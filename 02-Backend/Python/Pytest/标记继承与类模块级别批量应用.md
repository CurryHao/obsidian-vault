# 标记继承与类模块级别批量应用

## 📌 一句话总结
> 这是标记体系从“单兵作战”升级为“集团军作战”的关键能力。通过类和模块级别的批量应用，你能将标记从重复的装饰器噪音中解放出来，实现**一处声明，全局生效**。

我将从**类级继承**、**模块级全局变量**、**继承合并规则**以及**参数化覆盖陷阱**四个维度，为你彻底讲透这套批量机制。

## 🎯 核心概念

### 1. 类级别批量应用：一次装饰，全方法继承

当一个测试类被标记后，该类下的**所有测试方法**都会自动继承该标记。这是组织大型测试类最基础的手段。

```python
import pytest

# 类级标记：该类下所有测试方法都变为 smoke 和 slow
@pytest.mark.smoke
@pytest.mark.slow
class TestHeavyComputation:
    def test_fibonacci(self):
        # 自动携带 smoke, slow
        pass
    
    def test_matrix_multiply(self):
        # 自动携带 smoke, slow
        pass
    
    # 方法级标记会追加，而非覆盖
    @pytest.mark.integration
    def test_database_load(self):
        # 最终标记为：smoke, slow, integration
        pass
```
**执行效果**：`pytest -m slow` 会运行该类所有方法；`pytest -m integration` 只运行 `test_database_load`。

### 2. 模块级别批量应用：`pytestmark` 全局变量（最强武器）

在测试文件的**模块顶层**定义 `pytestmark` 变量，该模块内的**所有测试类和函数**都会继承该标记。这是**减少重复代码最极致**的方式。

```python
# test_whole_module.py
import pytest

# 单标记写法
pytestmark = pytest.mark.slow

# 多标记写法（推荐用列表）
pytestmark = [
    pytest.mark.slow,
    pytest.mark.integration,
    pytest.mark.payment
]

# 类依然可以追加自己的标记
@pytest.mark.smoke
class TestPayment:
    # 实际标记：slow, integration, payment, smoke
    def test_credit_card(self): pass

def test_standalone():
    # 实际标记：slow, integration, payment（函数继承了模块级）
    pass
```

**关键限制**：`pytestmark` 只对**直接定义在该模块中**的测试生效，对通过 `conftest.py` 导入的固件或外部模块中的基类**无效**。

### 3. 继承与覆盖规则：“叠加”而非“替换”

这是最容易混淆的核心机制。`pytest` 对标记的处理逻辑是**合并（Union）**，而非子类覆盖父类的重写逻辑。

#### 场景一：基类标记自动被子类继承
```python
@pytest.mark.slow
class BaseTest:
    def test_base(self): pass

@pytest.mark.integration  # 追加标记
class ChildTest(BaseTest):
    def test_child(self): pass
    # 实际标记：slow + integration
```

#### 场景二：同名标记的参数冲突（`xfail` / `skipif` 的特殊性）
当父类和子类都使用了 `xfail` 且参数不同时，`pytest` 会**优先采用子类（更具体）的参数**，但仅限 `xfail` 和 `skipif` 这类带条件的标记。**其他自定义标记无条件合并**。

```python
@pytest.mark.xfail(reason="父类预期失败")
class BaseAPI:
    def test_get(self): pass

@pytest.mark.xfail(strict=True, reason="子类严格模式")  # 子类覆盖
class ChildAPI(BaseAPI):
    def test_get(self): pass
    # 执行时，xfail 参数取自子类（strict=True），而非父类
```

### 4. 参数化（`parametrize`）的继承特例：完全覆盖

**这是唯一一个子类会“完全覆盖”父类而非合并的标记**。如果父类对 `x` 参数进行了参数化，子类重新参数化 `x`，则父类的参数化列表**被丢弃**。

```python
@pytest.mark.parametrize("x", [1, 2, 3])
class BaseMath:
    def test_square(self, x): pass

@pytest.mark.parametrize("x", [100, 200])  # 覆盖父类！
class ChildMath(BaseMath):
    def test_square(self, x):
        # 只会跑 100 和 200，不会跑 1, 2, 3
        pass
```

### 5. 与 `usefixtures` 的深度结合：批量挂载副作用

`usefixtures` 是**唯一一个可以同时挂载在类/模块上，且对所有方法生效**的特殊标记。它和 `pytestmark` 配合，可以彻底消灭函数参数的声明。

```python
# 模块级：每个测试都自动重置缓存+事务回滚
pytestmark = [
    pytest.mark.usefixtures("reset_cache", "db_transaction"),
    pytest.mark.slow
]

# 类级：额外挂载日志捕获
@pytest.mark.usefixtures("capture_logs")
class TestOrderService:
    def test_create_order(self):
        # 实际挂载：reset_cache, db_transaction, capture_logs
        pass
```

### 6. 极易踩中的 3 个致命陷阱

| 陷阱现象 | 根本原因 | 解决方案 |
| :--- | :--- | :--- |
| **`pytestmark` 拼写错误（写成 `pytest_mark`）导致模块级标记失效** | 变量名必须**严格**为 `pytestmark`，无下划线 | 收集模式检查：`pytest --collect-only -q`，若数量不对，立即检查拼写 |
| **子类中的 `xfail` 未覆盖父类，导致预期行为混乱** | 误以为 `xfail` 会被合并。实际上子类 `xfail` 会替代父类 | 若想合并，需在子类中显式 `@pytest.mark.xfail` 并传入父类参数组合 |
| **类级标记导致参数化生成的用例数量暴增** | 类标记会作用于参数化产生的**所有**子用例（如 3 个参数 × 类级标记），但不会改变数量本身 | 这并非错误，但若你想对部分参数用例取消标记，需在 `pytest.param(..., marks=[])` 中显式剔除 |

### 7. 诊断技巧：查看继承后的“最终标记集”

在调试时，你可以利用 `request.node.iter_markers()` 查看测试方法实际携带的标记列表：

```python
def test_debug(request):
    # 打印该测试最终携带的所有标记（包含继承来的）
    markers = [m.name for m in request.node.iter_markers()]
    print(f"最终标记: {markers}")
    # 输出示例：['smoke', 'slow', 'integration']
```

或在命令行中结合 `--collect-only -v` 查看节点路径，部分IDE也会在测试树中显示标记徽章。

### 8. 终极决策矩阵

| 应用范围 | 语法 | 适用场景 | 与父级标记关系 |
| :--- | :--- | :--- | :--- |
| **单测试函数** | `@pytest.mark.smoke` | 特定用例特殊标记 | 追加 |
| **整个测试类** | 类声明上方加装饰器 | 同一模块内的多个方法共享一组行为 | 追加 |
| **整个模块** | `pytestmark = [ ... ]` | 同一文件内**所有**测试（含函数、类）共享基础属性 | 追加（基类标记依然有效） |
| **跨模块全局** | `conftest.py` + 钩子动态添加 | 基于目录的批量标记（如 `tests/integration/` 下所有用例自动加 `integration`） | **需自己实现钩子逻辑** |
