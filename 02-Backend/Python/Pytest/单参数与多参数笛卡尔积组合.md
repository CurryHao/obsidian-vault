# 单参数与多参数笛卡尔积组合

## 📌 一句话总结
> 这是PyTest参数化机制从**“数据驱动”**迈向**“组合覆盖”**的关键分水岭。我将直接点明核心区别，并揭示实现真正笛卡尔积的“堆叠装饰器”技巧。

## 🎯 核心概念

### 1. 核心认知：显式组合 ≠ 笛卡尔积

许多初学者会误以为在单个 `@pytest.mark.parametrize` 中放入多个列表就能自动获得笛卡尔积，这是**错误的**。

- **单参数**：生成 N 个测试用例（N = 列表长度）。
- **多参数显式组合**：在同一个装饰器中传入 `argnames` 和 `argvalues`，**生成 N 个测试用例（N = 元组数量）**。这本质上是“手动配对”，而非“自动排列组合”。
- **真正的笛卡尔积（全排列组合）**：必须通过**堆叠（Stacking）多个 `parametrize` 装饰器**来实现，生成 M × N 个用例。

### 2. 实战对比：三种写法与产生的用例数

假设我们有两个维度：`operation`（加法/乘法）和 `numbers`（正数/负数/零）。

#### 写法一：单参数（单一维度）
```python
@pytest.mark.parametrize("x", [1, 2, 3])
def test_single(x):
    assert x > 0
# 生成 3 个用例
```

#### 写法二：多参数显式组合（手动配对，非笛卡尔积）
```python
@pytest.mark.parametrize("op, x, y", [
    ("add", 1, 2),   # 用例1：1+2
    ("mul", 3, 4),   # 用例2：3*4
])
def test_explicit(op, x, y):
    # 只会生成 2 个用例，数据严格按元组位置绑定
    pass
```

#### 写法三：真正的笛卡尔积（堆叠装饰器）
```python
# 下方装饰器先解析（离函数最近的最先执行，但实际逻辑是构造全排列）
@ pytest.mark.parametrize("op", ["add", "mul"])        # 2 种操作
@ pytest.mark.parametrize("x", [1, 2])                 # 2 个数
@ pytest.mark.parametrize("y", [10, 20])               # 2 个数
def test_cartesian_product(op, x, y):
    # 生成 2 * 2 * 2 = 8 个用例！
    # 自动覆盖：add/1/10, add/1/20, add/2/10, add/2/20, mul/1/10...
    if op == "add":
        assert x + y == x + y
    else:
        assert x * y == x * y
```
**执行命令验证**：`pytest -v` 会显示 8 个节点，如 `test_cartesian_product[mul-2-20]`。

### 3. 进阶：参数化 + Fixture 的笛卡尔积（`indirect` 的威力）

当你想让 Fixture 也参与排列组合时，使用 `indirect=True` 让参数值先传入 Fixture，再传入测试函数。

```python
import pytest

# 定义两个 Fixture，分别接收参数
@pytest.fixture
def db_connection(request):
    # request.param 来自参数化
    db_type = request.param
    return f"Connected to {db_type}"

@pytest.fixture
def user_role(request):
    return f"Role: {request.param}"

# 堆叠装饰器：让 Fixture 和普通参数都参与笛卡尔积
@ pytest.mark.parametrize("db_connection", ["mysql", "sqlite"], indirect=True)
@ pytest.mark.parametrize("user_role", ["admin", "guest"], indirect=True)
@ pytest.mark.parametrize("timeout", [10, 30])  # 普通参数也组合进去
def test_multi_fixture_cartesian(db_connection, user_role, timeout):
    # 生成 2 * 2 * 2 = 8 个用例
    print(f"{db_connection}, {user_role}, timeout={timeout}")
```
这个模式特别适用于**跨浏览器测试**（Chrome/Firefox） × **用户类型**（登录/未登录） × **分辨率**（1920/1080）的全组合覆盖。

### 4. ID 命名策略：让 100+ 个用例可读

笛卡尔积会导致用例数量指数级爆炸。为了让 `pytest -v` 的输出一目了然，必须自定义 `ids`。

#### 策略一：在 `pytest.param` 中注入 ID（最推荐）
```python
@pytest.mark.parametrize("op", [
    pytest.param("add", id="加法"),
    pytest.param("mul", id="乘法"),
])
@pytest.mark.parametrize("x", [
    pytest.param(1, id="正数"),
    pytest.param(-1, id="负数"),
])
def test_with_ids(op, x):
    # 生成的用例名称会变成: test_with_ids[加法-正数]
    pass
```

#### 策略二：`ids` 参数传入函数（动态生成）
```python
def id_func(val):
    return f"val_{val}"

@pytest.mark.parametrize("x", [1, 2, 3], ids=id_func)
@pytest.mark.parametrize("y", [10, 20], ids=id_func)
def test_dynamic_ids(x, y):
    pass
```

### 5. 极易踩中的 3 个陷阱（必看！）

| 陷阱现象 | 根本原因 | 解决方案 |
| :--- | :--- | :--- |
| **笛卡尔积导致测试数量爆炸（CI 超时）** | 堆叠了 4 个装饰器，每个有 10 个值，生成了 10^4 = 10000 个用例 | 考虑使用 `pytest.mark.parametrize` 的 `pytest.param(..., marks=pytest.mark.skip)` 条件跳过部分组合；或仅在夜间回归中启用全量笛卡尔积 |
| **堆叠顺序与 Fixture 执行顺序混乱** | 离函数最远的装饰器先生效，但 Fixture 的 `scope` 会影响资源创建时机 | 记住：**最底下的装饰器（紧贴 def）最先展开**，但执行顺序依然遵循 Fixture 依赖的 DAG（有向无环图），与装饰器顺序无关 |
| **显式组合误用为笛卡尔积（漏测风险）** | 写了 `("x,y", [(1,2), (3,4)])`，期望测试 `1/3` 和 `2/4` 的组合，结果只跑了 `1+2` 和 `3+4` | 如果你要的是所有交叉组合，**必须用多个 `@parametrize` 堆叠** |

### 6. 决策矩阵：我该用哪种？

| 测试场景 | 推荐方式 | 生成的用例数 |
| :--- | :--- | :--- |
| 输入多组独立数据（如 CSV 行） | **多参数显式组合**（单个装饰器 + 元组列表） | = 元组数量 |
| 需要测试所有 OS × 所有浏览器 × 所有分辨率 | **堆叠装饰器（笛卡尔积）** | = Len(OS) * Len(Browser) * Len(Resolution) |
| 测试函数参数既有普通值，又有 Fixture | **堆叠 + `indirect=True`** 混合 | 全组合 |
| 生产环境全量回归（性能敏感） | 使用 `pytest.mark.parametrize` + 条件式 `skip` 或 `xfail` 精简组合 | 动态缩减 |

### 7. 终极实战：组合测试与标记（Marker）的结合

你可以给笛卡尔积中的**特定组合**打上标记，比如某个 `op` + `x` 的组合是冒烟测试：

```python
@pytest.mark.parametrize("op", ["add", "mul"])
@pytest.mark.parametrize("x", [
    pytest.param(1, marks=pytest.mark.smoke),  # 只对这个组合打标记
    pytest.param(2),
])
def test_with_markers(op, x):
    pass
```
执行 `pytest -m smoke` 时，只会运行 `op="add"` 且 `x=1` 以及 `op="mul"` 且 `x=1` 的组合（因为 `smoke` 标记挂在了 `x=1` 上，它会与所有 `op` 组合）。

您现在是想**覆盖多浏览器/多设备的矩阵测试**，还是想**对某业务规则做数据驱动的全排列验证**？告诉我您要测试的具体维度和取值范围，我可以直接为您生成一段“堆叠式笛卡尔积”的模板代码，并附带上预估的用例总数和性能优化建议。您选哪个场景？
